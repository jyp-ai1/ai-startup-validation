# Sprint 4 Kickoff — Decision Workshop

> **Status:** P0 in progress

## Product philosophy — "결론을 늦추는 AI"

| Sprint | Principle |
|--------|-----------|
| 1 | 모르면 모른다 |
| 2 | 읽고 말한다 |
| 3 | 기준을 맞춘다 |
| 4 | **먼저 중요한 사실을 이해하고, 그다음 무엇을 결정할지 함께 정한다** |

결정도 같이 정한다 — but **Insight before Decision**.

---

## Founder mental model (after Review)

```
1. 우리 사업 괜찮은가?
2. 왜 그렇게 평가했지?
3. 그러면 나는 뭘 해야 하지?
4. 같이 정리해보자.
```

LaunchLens must mirror:

```
Review → Insight → Decision → Workshop
```

**Not:** Review → Decision Candidate (founder asks *"왜?"*)

**Yes:** Review → **Key Insight** → Candidate (founder says *"아 그렇구나."*)

---

## Full loop

```
Review
    ↓
Key Insight (1)             ← Sprint 4 P0 step 1
    ↓
Decision Candidate (1)      ← Sprint 4 P0 step 2 — because of insight
    ↓
Decision Agreement        ← founder confirms topic
    ↓
Workshop                    ← P1: Options · Trade-off
    ↓
Simulation                  ← P2: Re-review
```

Good PM never opens with *"이거 결정하세요."* — first *"왜 이게 중요한지"*.

## P0 — Key Insight + Decision Candidate (ship only this)

### Step 1 — Key Insight (1개 · 발견 · not advice)

```
이번 검토에서는
시장 진입 전략에 대한 가정이 아직 명확하지 않아,
이 부분이 사업성 평가에 가장 큰 영향을 주는 것으로 보였습니다.
```

**Not:** *"가장 중요한 문제입니다."* (judgment) · **Yes:** observation + impact

User Feeling: *"아 그렇구나."*

### Step 2 — Decision Candidate (insight → therefore · invitation, not question)

```
그래서 다음은
시장 진입 전략을 함께 정리해보는 것이
가장 도움이 될 것 같습니다.
```

**Not:** *"어떨까요?"* (question) · **Yes:** PM invitation — *"도움이 될 것 같습니다."*

Founder:

| Choice | |
|--------|--|
| **이 주제로 같이 보기** | Workshop start (not "승인") |
| 다른 주제 선택 | Redirect |
| 직접 입력 | e.g. *"기술 차별화"* → AI adjusts |

Founder override example:

```
좋습니다.
그러면 기술 차별화부터 함께 정리해 보겠습니다.
```

### Step 3 — Agreement (workshop start, not approval)

Buttons:

```
이 주제로 같이 보기
다른 주제 선택
직접 입력
```

Founder is **starting a workshop**, not approving AI.

→ Workshop entry (P1)

## Expression guidelines (rev. 5 — implementation lock)

| Element | Rule | Example |
|---------|------|---------|
| **Insight** | Discovery = **관찰 + 영향**. No advice, no judgment. | ✅ *"…가정이 아직 명확하지 않아, …영향을 주는 것으로 보였습니다."* |
| | Ban: `가장 중요`, `추천`, `해야 합니다`, `문제입니다` | ❌ *"가장 중요한 문제입니다."* |
| **Candidate** | PM **invitation** — not a question | ✅ *"…함께 정리해보는 것이 가장 도움이 될 것 같습니다."* |
| **Agreement** | **Workshop start** — not AI approval | ✅ *"이 주제로 같이 보기"* |

### One-line Sprint 4 experience

```
Review → 이번 검토에서 가장 크게 보인 점 → 그래서 다음으로 같이 보면 좋은 주제 → 같이 보기 → Workshop
```

### P0 — do NOT ship

- Insight/Candidate 여러 개 동시 노출
- Option A/B/C · Trade-off · 추천 전략 · Simulation
- AI agenda ①②③ dump
- `가장 중요합니다` 같은 단정 표현

### P0 implementation scope

1. Review 종료 후 **Key Insight 1개** (관찰 + 영향)
2. Insight 기반 **Decision Candidate 1개** (PM 초대)
3. Agreement: **이 주제로 같이 보기** / 다른 주제 선택 / 직접 입력
4. Agreement → Workshop 진입 (P1 scope)

### User Feeling (P0)

> *"맞네."* → *"그럼 이걸부터 같이 보면 되겠구나."*

## Product Rules

1. 대표의 **사고**를 더 명확하게 만드는가?
2. 대표의 **결정**을 더 쉽게 만드는가?

**Insight test:** Candidate without Insight → founder asks *왜?* · Insight first → *아 그렇구나.*

---

## PR checklist (P0)

1. **Insight가 Candidate보다 먼저**인가?
2. Insight가 Review **근거**에서 나오는가? (추측 ❌)
3. AI가 **주제·결론을 대신 정하지** 않는가?
4. **다음 대화**를 이어가고 싶게 만드는가?
