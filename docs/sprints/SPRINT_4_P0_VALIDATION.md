> **Status:** Active · **P1 blocked until H1 Evidence Review**

> **Prerequisite:** Sprint 4 P0 shipped (Insight → Candidate → Agreement)

---

## LaunchLens Learning Sprint — **FROZEN** (no new frames until 5 sessions complete)

```
One Sprint → One Hypothesis → One Behavior → Evidence → Confidence → Decision
```

**Golden rules:**

1. **Evidence가 나오기 전에는 제품을 바꾸지 않는다.**
2. **대표 5명 세션 종료까지 새로운 프레임·문서·가설 추가하지 않는다.**

### Decision (three only)

| Decision | Meaning |
|----------|---------|
| **Keep** | Hypothesis holds — next step proceeds |
| **Kill** | Hypothesis rejected |
| **Refine** | Hypothesis holds — re-test expression or scope |

### Confidence (Evidence grade)

Not about numbers — **does the team share the same level of certainty?**

| Confidence | Meaning |
|--------------|---------|
| **High** | Same Behavior repeats · interpretation clear |
| **Medium** | Behavior repeats · cause ambiguous (Insight vs facilitator?) |
| **Low** | Few cases · multiple readings |

```
Evidence → Confidence → Decision (Keep / Kill / Refine)
```

### Evidence Review — one question

> **"이 Evidence만으로 다음 Sprint를 정당화할 수 있는가?"**

| Answer | Action |
|--------|--------|
| **YES** | Keep (or Refine if scoped) |
| **NO** | Observation continues — no product change |

### Roles

| Role | Delivers |
|------|----------|
| **Dev** | Experience that induces **Behavior** |
| **PM** | **Evidence** |
| **CPO** | **Decision** |

## Operating principle — Sprint 4 (H1 + B1)

Each validation sprint: **one hypothesis · one behavior · evidence only.**

### Hypothesis H1

> Review 직후 Insight는 대표의 사고를 **다음 단계로 이동**시킨다.

### Behavior B1 (what we count)

> Review 이후 founder shows acceptance shift — typically **Pause → Sentence → Question**, e.g. *"아 그렇구나."*

Not UI metrics. **Observable founder behavior** after Insight.

### Future Hypotheses (observe only — not this sprint)

Not a feature backlog — **learning roadmap:**

| ID | Future Hypothesis |
|----|-------------------|
| **H2** | Candidate가 Workshop으로 자연스럽게 이어지는가? |
| **H3** | Workshop가 대표의 결정을 쉽게 만드는가? |
| **H4** | Option 비교가 신뢰를 높이는가? |

Record signals during sessions → **Future Hypotheses** table. Do not judge until scheduled sprint.

## Sprint flow (Sprint 4)

```
Hypothesis H1 + Behavior B1
        ↓
  대표 5명
        ↓
  Observation (Pause · Sentence · Question)
        ↓
  Evidence + Confidence
        ↓
  Evidence Review (one question)
        ↓
  Keep / Kill / Refine
        ↓
  다음 Sprint (H2 only after H1 Keep)
```

**One Sprint · One Hypothesis · One Behavior · Evidence First.**

## What LaunchLens validates

LaunchLens = **대표의 사고를 구조화하는 AI PM**.

Validation must measure:

> **대표의 사고가 어떻게 변화했는가?**

Not UI clicks. Not PASS/FAIL.  
**Thinking Shift** → **Product Response** (AI PM's next move matched to founder's thinking stage).

This is LaunchLens's differentiated validation methodology — not generic UX testing.

---

## One philosophy, four sprints

```
Sprint 1   모르면 모른다
Sprint 2   읽고 말한다
Sprint 3   기준을 맞춘다
Sprint 4   무엇을 결정해야 하는지 같이 찾는다
```

Core = **사고 과정**. Sprint 5 trap = Option / Trade-off / Simulation feature sprawl.

## Validation frame (rev. 4 — final)

```
Observation
  ① First Pause
  ② First Sentence
  ③ First Question

        ↓

Thinking Shift
  (대표의 사고가 어떻게 바뀌었는가?)

        ↓

Product Response
  (AI PM은 다음에 무엇을 해야 하는가?)
```

**Design center:** Pause = behavior · Sentence = expression · **Thinking Shift = what changed in the founder's mind** · Product Response = PM action matched to that stage.

---

## Real session rhythm

```
Review
    ↓
(5–15초)              ← ① First Pause
    ↓
"아..."               ← ② First Sentence
    ↓
첫 질문                ← ③ First Question
    ↓
(내부) '시장 진입이 중요하구나'  ← Thinking Shift (facilitator infers + confirms if needed)
    ↓
Product Response      ← what AI PM should do next
```

We don't ship the question — we ship **a new thought** (e.g. *"시장 진입 전략이 중요하다"*).

---

## ① First Pause

**Where did thinking stop?**

| Pause at | Often means |
|----------|-------------|
| Review 끝 | Review 결과 소화 |
| Insight | Insight landing or resisting |
| Candidate | Topic proposal landing |
| Agreement | Commitment hesitation |
| No pause — 바로 클릭 | Flow accepted or disengaged |

Record: location · ~duration · context.

---

## ② First Sentence

**First thing out loud** — often unconscious. Verbatim only.

Examples: *"아 그렇구나."* · *"잠깐."* · *"음..."* · *"왜?"* · *"맞아요."*

---

## ③ First Question

After pause + sentence. Taxonomy:

| First question | Typical Thinking Shift path |
|----------------|----------------------------|
| *"왜?"* / *"왜 중요?"* | 아직 논리를 신뢰하지 않음 |
| *"그럼 어떻게?"* | 문제 인식 → **해결 탐색** |
| *"다른 방법은?"* | 하나의 답이 아니라 **비교** |
| *"뭘 해야?"* | **실행** 욕구 (Candidate가 지시로 읽힘) |
| *"모르겠"* | Review / Debrief 미완 |

---

## Thinking Shift

**Not interpretation of UI — record how founder's thinking changed.**

Facilitator infers from Pause + Sentence + Question (+ optional gentle *"지금 어떤 생각이 드세요?"* **after** session only if needed).

| Observation signal | Thinking Shift (examples) |
|--------------------|---------------------------|
| *"아 그렇구나."* | AI의 관점을 **받아들이기 시작** |
| Pause at Insight, then ack | **중요성을 받아들이는 중** |
| *"왜?"* | 아직 **논리를 신뢰하지 않음** |
| *"그럼 어떻게?"* | 문제 인식 → **해결 탐색으로 전환** |
| *"다른 방법은?"* | **비교**를 원함 (single answer insufficient) |
| Internal: *"시장 진입이 중요하구나"* | **새로운 사고** — Insight succeeded |
| *"뭘 해야?"* | 실행 앞섬 — Candidate may have felt like instruction |

Write **one line** per session — the thought that changed, not the UI element.

---

## Product Response

**Not "build Workshop."** → **AI PM's next move matched to thinking stage.**

| Thinking Shift | Product Response |
|----------------|------------------|
| 아직 중요성을 이해 못함 | **Insight 강화** · Debrief |
| 중요성은 이해함 · 해결 탐색 | **Workshop** (agreed topic) |
| 비교를 원함 | **Option 비교** (P1 options-first) |
| 실행을 원함 | **Action Plan** (later — not P1 default) |
| Review 자체 미이해 | **Debrief** · score driver |
| 논리 불신 | Insight evidence · discovery tone |

Product Response = *what the AI PM should do next*, not a feature ticket.

## Validation sheet (per session)

| Field | Example |
|-------|---------|
| Session # | 3 |
| **① Pause** | Insight (8초) |
| **② Sentence** | *"아 그렇구나."* |
| **③ Question** | *"다른 방법은?"* |
| **Thinking Shift** | Insight 수용 → **비교를 원함** |
| **Product Response** | Workshop · Option 비교 |
| **Confidence** | High / Medium / Low |

### Confidence (interpretation certainty)

Our confidence in Thinking Shift + Product Response — **not** founder confidence.

| Level | When |
|-------|------|
| **High** | Founder said it directly — e.g. *"왜 이게 중요하죠?"* → Insight gap is clear |
| **Medium** | Long pause but reason inferred |
| **Low** | Multiple interpretations possible — note alternatives in Notes |

Use Confidence in Synthesis: **2/5 Low** ≠ **4/5 High** for the same pattern.

### Full row example

| Observation | Thinking Shift | Product Response | Confidence |
|-------------|----------------|------------------|------------|
| Pause: Insight (8초) | 중요성을 받아들이는 중 | (B1 path) | Medium |
| Sentence: *"아 그렇구나."* | Insight 수용 · **B1** | — | High |
| Question: *"다른 방법은?"* | 비교를 원함 | Workshop (options-first) | High |

One row per session → **next Sprint rationale is obvious**.

### Counter-example

```
Pause:       Review 끝 (10초)
Sentence:    "음..."
Question:    "왜 이게 중요하죠?"

Thinking Shift
  아직 중요성을 이해 못함 · 논리 불신

Product Response
  Insight 강화 · Debrief — not Workshop
```

## Success vs failure (by Thinking Shift — not PASS/FAIL)

| Thinking Shift (dominant) | Meaning | Product Response |
|---------------------------|---------|------------------|
| Insight 수용 + 해결 탐색 | **Sprint 4 success** | Workshop |
| 비교를 원함 | Success + scope hint | Option 비교 |
| 아직 중요성 이해 못함 | Insight / Debrief gap | Insight 강화 |
| 논리 불신 | Insight = judgment | discovery tone |
| Review 미이해 | Review layer | Debrief |
| 실행만 원함 | Candidate = instruction | invite copy |

**Target (5 sessions):** ≥3 → Insight 수용 → 해결 탐색 or 비교  
**Block P1 if:** ≥3 → 아직 중요성 이해 못함 or Review 미이해

## Synthesis (after 5 sessions)

**H1 only.** Do not fix product until Evidence Review.

### H1 Evidence table

| Hypothesis | Evidence | Confidence | Decision |
|------------|----------|------------|----------|
| **H1:** Insight가 사고를 이동시킨다 | e.g. #1–#5 B1 count | | Keep / Kill |

**Future Hypotheses** (observe only — not H1): H2 Candidate · H3 Workshop · H4 Options

Rules: **High + ≥3 sessions** → strong H1 Evidence · **2 ≠ 4** — count matters

### Thinking Shift rollup

| Thinking Shift | Count | Product Response (consensus) |
|----------------|-------|------------------------------|
| 해결 탐색 | /5 | Workshop |
| 비교를 원함 | /5 | Option 비교 |
| 중요성 미수용 | /5 | Insight / Debrief |
| 논리 불신 | /5 | copy fix |
| Review 미이해 | /5 | Debrief |

### CPO line (replaces PASS/FAIL)

> **Product Response for Sprint 4.x:** _______________

Examples:

- *Workshop — standard, agreed topic first*  
- *Workshop — options-first (3/5 asked for comparison)*

## Facilitator script

**Opening (only):** *"PDF 또는 사업 문서를 올려보세요."*

**During session — capture:**

1. Pause (where · how long)  
2. Sentence (verbatim)  
3. Question (verbatim)

**After session — infer:**

4. Thinking Shift (one line)  
5. Product Response (PM next move)  
6. **Confidence** (High / Medium / Low)

**Do NOT:** explain product · PASS/FAIL in room · lead Thinking Shift · **fix product between sessions**

Optional post-session (only if unclear): *"방금 어떤 점이 가장 크게 느껴지셨어요?"* — to validate Thinking Shift inference.

## Learning mode — Freeze period (sessions 1–5)

**Shift:** building org → **learning org.**

Until Synthesis is complete:

```
대표 1 → Observation 기록
대표 2 → Observation 기록
대표 3 → Observation 기록
대표 4 → Observation 기록
대표 5 → Synthesis (patterns only)
```

| Rule | |
|------|--|
| **Product code/copy** | **No changes** during sessions 1–4 |
| **"이거 고치면 되겠다"** | Write in Notes — do not ship |
| **Why wait** | Session 1 reaction may ≠ session 5 pattern |
| **After Synthesis** | Fix sprint scoped from **Pattern table + Confidence** |

Only artifact that grows during freeze: **Observation Sheet** (+ facilitator Notes).

**Internal only (not in official frame):** Decision Readiness — *"대표는 지금 어떤 결정을 할 준비가 되었는가?"* — PM mental model when inferring Thinking Shift.

## Sprint exit criteria (H1 only)

Validation sprint is **done** when H1 is resolved with Evidence:

> **Insight 이후 대표의 사고가 다음 단계로 이동하는가?**

Deliverables:

- [ ] 대표 **5명** — Observation capture complete  
- [ ] **H1 Evidence table**  
- [ ] **Evidence Review** — H1 **Keep / Kill**  
- [ ] P1 · H2 — **after** H1 Decision only  

### H1 Evidence table (required)

| Hypothesis | Behavior | Evidence | Confidence | Decision |
|------------|----------|----------|------------|----------|
| H1: Insight가 사고를 이동시킨다 | B1: *"아 그렇구나"* | e.g. 4/5 | High / Med / Low | Keep / Kill / Refine |

**Observe → Future Hypotheses:** H2 Candidate · H3 Workshop · H4 Options — not H1 pass/fail.

**Observation** = raw capture. **Evidence** = repeated facts for H1 only.

---

## Evidence Review (sprint close)

**One question:**

> **이 Evidence만으로 다음 Sprint를 정당화할 수 있는가?**

YES → Keep or Refine · NO → Observation continues · Kill only with High-confidence counter-Evidence

Scope: **H1/B1 only.** H2+ remain Future Hypotheses.

---

## Freeze period — Future Hypotheses vs Evidence

| Bucket | Rule |
|--------|------|
| 🔮 **Future Hypotheses** | Next sprints to validate (H2–H4) — not ideas, not features |
| 📊 **Evidence** | Repeated **Behavior** observations for **current H1/B1** |
| 🚀 **Decision** | Keep / Kill — **Evidence only** |

Sessions 1–4: capture only. Session 5: H1 Evidence + Evidence Review.

**Evidence가 나오기 전에는 제품을 바꾸지 않는다.**

**Deliverable = Evidence**, not PR.

## Scope

### In

- 5 sessions · full sheet each  
- Thinking Shift + Product Response per session  
- Synthesis → CPO **Product Response** line

### Out

- P1 until Product Response consensus  
- PASS/FAIL labels  
- Feature build without Thinking Shift data

### Forbidden

- Workshop during validation  
- Recording question without Pause + Sentence  
- Product Response without Thinking Shift  
- **Product fixes during sessions 1–4** (Notes only until Synthesis)
