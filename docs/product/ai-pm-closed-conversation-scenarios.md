**상태:** CPO 재검토 패키지 제출 · 구현·병합·배포 보류

**시나리오 본문 기준 SHA:** `5263e83e` · **이전 패키지 SHA:** `d151b25d`  
**Production:** `0b465226` 불변 · Merge 금지  
**CPO 판정:** 수정 후 재검토. R1–R4는 시나리오 기대를 먼저 고친다. 코드 변경은 재승인 후.

이 문서는 기능을 더 만들기 전에, 여러 사업의 **시작 → 이해 갱신 → 판단 변화 → 다음 행동**을 CPO가 한 번에 검토하기 위한 기대 대화입니다.  
질문 문구 모음이 아닙니다. 각 답 이후 AI가 무엇을 알고, 무엇을 모르며, 판단을 왜 바꾸는지가 검수 대상입니다.

승인 전에는 회귀 테스트·대규모 수정을 넣지 않습니다. 승인 후 이 기대를 테스트 케이스로 옮깁니다.

## 읽는 법

각 턴은 다음을 가집니다.

| 칸 | 의미 |
|---|---|
| AI 질문 | 지금 남은 핵심 불확실성 하나 |
| 선택지 | 해당 사업에만 맞는 객관식. 항상 `기타` · `아직 모르겠음` |
| 창업자 | 선택 또는 자유 입력 |
| 이해 변화 | 사실 / 가정 / 미확인이 어떻게 바뀌는지. 없으면 `변화 없음`을 명시 |
| 판단 전→후 | customer · problem · solution · customerChange · 결론. 안 바뀌면 이유를 씀 |
| 다음 | 이미 닫힌 슬롯을 되묻지 않는 다음 질문 또는 종료 |
| 금지 | 이 턴에서 하면 안 되는 것 |

공통 분기는 시나리오에 나눠 심습니다. 모든 조합을 열거하지 않습니다.

| 분기 | 담당 시나리오 |
|---|---|
| 구체 객관식 | 전 시나리오 |
| `아직 모르겠음` → Fact 미승격, 다른 공백으로 이동 | S1 T3, S3 T4 |
| `기타` / 자유 입력 | S2 T4, S5 T5 |
| 이미 답한 항목 재질문 금지 (#197 재현) | S1 T2→T3 |
| 답변 모순 (창업자 입력 → Fact contradicted → 재확인) | S4 T6–T7 |
| 증거 없는 성급한 긍정 판단 금지 | S3 전체, S6 T7 |
| 사업 유형별 질문·선택지 차이 | S1 vs S2 vs S6 첫 객관식 |
| 새 답이 이해·판단에 반영 | S1 T2, S5 T7–T8 |

현재 #197 함수 경로에서 이미 깨진 기대는 시나리오에 **올바른 기대**로 적고, `[현재 이탈]`로 표시합니다.

## S3 · B2B 업무 자동화 SaaS

**유형:** B2B SaaS · 증거 약함  
**초기 입력:**

```
서비스: 중소 제조사의 견적·발주 메일을 읽어 엑셀 발주서를 자동으로 채우는 툴
대상: 직원 20–80명 제조사 영업관리자
문제: 메일·엑셀·ERP에 같은 숫자를 세 번 옮기다 오타가 난다
수익: 좌석 월 구독
```

**시작 이해:** 가정만. 자동화 효과를 사실로 쓰지 않음.

## S4 · 소비자 대상 구독 서비스

**유형:** B2C 구독  
**초기 입력:**

```
서비스: 아이 간식을 매주 집 앞으로 보내는 구독 박스

문제: 장을 볼 시간이 없고 과자 고르기가 피곤하다
수익: 월 구독
```

**시작 이해:** 가정 — 고객=맞벌이 부모, 문제=시간·선택 피로, 수익=월 구독. 아이(사용자)와 부모(구매자)가 다를 수 있음.

| 턴 | AI 질문 | 선택지 | 창업자 | 이해 변화 | 판단 전→후 | 다음 | 금지 |
|---|---|---|---|---|---|---|---|
| 1 | 부모가 지금 가장 귀찮아하는 점은 무엇인가요? | `장볼 시간이 없다` / `무엇을 줄지 고르기 싫다` / 기타 / 아직 모르겠음 | 무엇을 줄지 고르기 싫다 | 문제=선택 피로(확인). 시간 없음은 부가 가정 | problem `needs_check` | 누가 박스를 기다리는가 | |
| 2 | 박스를 가장 반기는 사람은 누구인가요? | `아이` / `부모` / 둘 다 / 기타 / 아직 모르겠음 | 아이 | 사용자=아이, 아직 구매자 미확인 | customer를 아이로만 닫지 말 것. 구매자 공백 유지 | 결제는 누가 하는가 | 아이를 결제자로 확정 금지 |
| 3 | 구독료는 누가 내나요? | `부모` / `조부모` / 기타 / 아직 모르겠음 | 부모 | 구매자=부모(확인) | customer/payer 분리 확인 | 지금은 간식을 어떻게 사나 | |

| 5 | 쿠팡 대신 이 박스를 고르는 이유는 무엇인가요? | `고민 없이 온다` / `더 건강하다` / 기타 / 아직 모르겠음 | 고민 없이 온다 | 차별=선택 제거(가설) | 가설. 건강 클레임 미선택 | 이미 돈 낸 부모가 있는가 | |
| 6 | 이미 구독료를 낸 부모가 있나요? | `있다` / `없다` / 기타 / 아직 모르겠음 | **모순 입력:** `사실 아이가 아니라 혼자 사는 20대가 메인이에요` | 충돌 기록. 기존 Fact를 즉시 폐기하거나 20대를 바로 Fact로 올리지 않음 | 고객 `contradicted`. 두 값을 동시에 Fact로 두지 않음. GO 금지 | 어느 쪽이 지금 맞는 고객인지 재확인. AI가 먼저 고객을 되묻는 흐름이 아님 | 모순을 무시하고 구독 성장 판단 금지 |

**S4 모순 상태 전이 (기대. 엔진 미실행):**

| 시점 | 고객 | 구매자 | 문제 | 기록 |
|---|---|---|---|---|
| T5 종료 | Fact 사용자=아이. Assumption 주 맥락=맞벌이 부모 | Fact=부모 | Fact=선택 피로(부모 맥락) | 충돌 없음 |

**종료 불확실성:** 정정된 고객의 선택 피로가 진짜인지, 결제 의사.  
**이 시나리오의 핵심:** 모순은 대화를 멈추지 않되, 이전 고객을 사실로 남기지 않음. AI가 닫힌 고객을 먼저 되묻지 않는다.

## 시나리오 종료 시 공통 기대

1. 결론이 GO이려면 고객·문제·구매자 확인 + 고객 변화를 지지하는 **외부 증거**가 있어야 한다. 위 6개는 모두 HOLD 또는 조건부다.
2. `아직 모르겠음`은 빈 칸을 유지하고 다른 공백으로 간다.
3. `기타`는 자유 입력을 가정으로 넣고 Fact로 올리지 않는다.
4. 확인된 슬롯(S1 문제, S4 정정 후 이전 고객)을 같은 의미로 다시 묻지 않는다.
5. 다음 행동은 사람·숫자·이번 주 단위여야 한다. 「더 조사하겠습니다」는 실패.
