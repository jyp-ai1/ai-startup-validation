# AI PM 완결형 대화 시나리오 초안 (CPO 일괄 검토용)

**상태:** CPO 검토 패키지 제출 · 구현 확대 정지  
**기준 PR:** [#197](https://github.com/jyp-ai1/ai-startup-validation/pull/197) · SHA `5263e83e`  
**Production:** `0b465226` 불변 · Merge 금지  
**아키텍처:** V3 living / review / next-question / judgment 유지. 엔진 재작성 없음.  
**본문:** 아래 S1–S6은 이미 작성된 시나리오를 재사용한다. 이 절 이후의 표는 검토용 요약이다.

이 문서는 기능을 더 만들기 전에, 여러 사업의 **시작 → 이해 갱신 → 판단 변화 → 다음 행동**을 CPO가 한 번에 검토하기 위한 기대 대화입니다.  
질문 문구 모음이 아닙니다. 각 답 이후 AI가 무엇을 알고, 무엇을 모르며, 판단을 왜 바꾸는지가 검수 대상입니다.

승인 전에는 회귀 테스트·대규모 수정을 넣지 않습니다. 승인 후 이 기대를 테스트 케이스로 옮깁니다.

## 읽는 법

각 턴은 다음을 가집니다.

| 칸 | 의미 |
|---|---|
| AI 질문 | 지금 남은 핵심 불확실성 하나 |
| 선택지 | 해당 사업에만 맞는 객관식. 항상 `기타` · `아직 모르겠음` |
| 창업자 | 선택 또는 자유 입력 |
| 이해 변화 | 사실 / 가정 / 미확인이 어떻게 바뀌는지. 없으면 `변화 없음`을 명시 |
| 판단 전→후 | customer · problem · solution · customerChange · 결론. 안 바뀌면 이유를 씀 |
| 다음 | 이미 닫힌 슬롯을 되묻지 않는 다음 질문 또는 종료 |
| 금지 | 이 턴에서 하면 안 되는 것 |

공통 분기는 시나리오에 나눠 심습니다. 모든 조합을 열거하지 않습니다.

| 분기 | 담당 시나리오 |
|---|---|
| 구체 객관식 | 전 시나리오 |
| `아직 모르겠음` → Fact 미승격, 다른 공백으로 이동 | S1 T3, S3 T4 |
| `기타` / 자유 입력 | S2 T4, S5 T5 |
| 이미 답한 항목 재질문 금지 (#197 재현) | S1 T2→T3 |
| 답변 모순 | S4 T6 |
| 증거 없는 성급한 긍정 판단 금지 | S3 전체, S6 T7 |
| 사업 유형별 질문·선택지 차이 | S1 vs S2 vs S6 첫 객관식 |
| 새 답이 이해·판단에 반영 | S1 T2, S5 T7–T8 |

현재 #197 함수 경로에서 이미 깨진 기대는 시나리오에 **올바른 기대**로 적고, `[현재 이탈]`로 표시합니다.

## S1 · 소상공인 배송·주문 SaaS

**유형:** B2B SaaS  
**초기 입력:**

```
서비스: 주문부터 배송까지 관리하는 B2B SaaS
대상: 반찬가게·꽃집 등 직접 배송 소상공인
문제: 주문과 배송을 따로 관리해야 함
수익: 월 구독
```

**시작 이해:** 가정 — 고객=직접 배송 소상공인, 문제=주문·배송 분리, 수익=월 구독. 사실 없음.  
**시작 판단:** 정보 부족. 4차원 `unknown`. 결제·반복 구매를 사실로 쓰지 않음.

|---|---|---|---|---|---|---|---|
| 1 | 고객이 지금 가장 불편해하는 점은 무엇인가요? | `주문과 배송을 따로 관리해야 함` / 기타 / 아직 모르겠음 | 주문과 배송을 따로 관리해야 함 | 문제: 가정→창업자 확인 | problem `unknown`→`needs_check`. 결론은 아직 GO 아님 | 누가 가장 먼저 쓸지 좁히기 | 문제를 `주문`으로 절단하지 않음. 전통주 선택지 금지 |
| 2 | 이 서비스를 실제로 가장 필요로 하는 사람은 누구인가요? | `반찬가게` / `꽃집` / `직접 배송 소상공인` / 기타 / 아직 모르겠음 | 반찬가게 | 고객: 소상공인 가정→반찬가게 확인. 꽃집은 아직 가정 | customer `unknown`→`clear`(ceo_confirmed). 결론: 고객은 어느 정도 파악. 나머지는 부족 | **구매자(누가 내는지).** 문제를 「맞나요?」로 되묻지 않음 | `[현재 이탈]` #197은 다음을 `핵심 불편은 「주문」으로 이해했습니다. 맞나요?`로 되돌림. 기대는 재질문 금지 |
| 3 | 월 구독 비용은 누가 지불하나요? | `반찬가게 사장이 냄` / `직원·주문이 쓰는 사람은 다름` / 기타 / 아직 모르겠음 | 아직 모르겠음 | 구매자 미확인으로 남김. 반찬가게를 결제자로 승격하지 않음 | 판단 결론 유지. customerChange/수익을 사실로 올리지 않음 | 수익 구조 확인 또는 대안. 구매자를 같은 말로 재질문하지 않음 | `아직 모르겠음`을 구매자 Fact로 저장 금지 |
| 4 | 수익은 어떤 구조로 발생하나요? | `월 구독` / `건당` / 기타 / 아직 모르겠음 | 월 구독 | 수익: 가정→확인 | solution/수익 `needs_check`. 「매출이 검증됨」 금지 | 지금 어떻게 주문·배송을 처리하는지 | 수수료·양조장 선택지 금지 |
| 5 | 지금은 이 문제를 어떻게 처리하나요? | `지금은 주문과 배송을 따로 관리함` / 엑셀·수첩 / 기타 / 아직 모르겠음 | 지금은 주문과 배송을 따로 관리함 | 대안=분리 관리(가정→확인). 경쟁 제품을 지어내지 않음 | 차별이 비어 있으므로 결론은 보류 | 반찬가게가 돈을 낼 만큼 시간이 줄어드는가 | 문제를 다시 묻지 않음 |

| 7 | 그 변화를 보여 줄 증거가 있나요? | `실제 결제·사용 증거가 있다` / `아직 없다` / 기타 / 아직 모르겠음 | 아직 없다 | 검증=미실시로 확인 | customerChange를 `clear`/`fact`로 올리지 않음. 결론 유지 또는 약화 | 종료 또는 반찬가게 3곳 확인 제안 | 결제 3건을 지어내 긍정 판단 금지. `[현재 이탈]` 결제 문장도 customerChange를 안 바꿈 — 기대는 「증거 없음」이 긍정 판단을 막거나 약화 |
| 8 | (판단 제시 후) 다음에 무엇을 하면 판단이 바뀌나요? | — | 창업자 확인 | — | **종료 판단:** HOLD. 고객=반찬가게(확인). 문제=주문·배송 분리(확인). 구매자 모름. 고객 변화=가설. 결제 증거 없음 | **다음 행동:** 이번 주 반찬가게 3곳에 「주문·배송을 한 화면에서 보면 시간을 줄이겠는가」를 묻고, 누가 구독료를 내는지만 확인 | 사업성 충분 / GO 금지 |

## S2 · 전통주 브랜드·유통

**유형:** 브랜드 + 유통  
**초기 입력:**

```
서비스: 소규모 양조장 전통주를 브랜드로 묶어 온라인·팝업으로 판매
대상: 전통주를 선물·취미로 찾는 30–40대
문제: 양조장마다 채널이 흩어져 소비자가 좋은 술을 발견하기 어렵다
수익: 제품 판매 + 양조장 입점 수수료
```

**시작 이해:** 가정 — 고객=30–40대 음용/선물, 문제=발견 어려움, 수익=판매+수수료. 사용자와 구매자가 다를 수 있음(선물). 사실 없음.

| 턴 | AI 질문 | 선택지 | 창업자 | 이해 변화 | 판단 전→후 | 다음 | 금지 |
|---|---|---|---|---|---|---|---|
| 1 | 지금 가장 크게 풀려는 불편은 무엇인가요? | `전통주를 현장에서·온라인에서 발견하기 어렵다` / `양조장이 판매 채널이 없다` / 기타 / 아직 모르겠음 | 전통주를 발견하기 어렵다 | 문제=발견(확인). 양조장 채널 부재는 미선택 가정으로 남김 | problem `needs_check` | 누가 가장 필요로 하는가. 배송 SaaS 선택지 금지 | 여행객·배송 누락 선택지 금지 |
| 2 | 이 브랜드를 가장 필요로 하는 사람은 누구인가요? | `선물하는 30–40대` / `전통주 애호가` / `양조장 사장` / 기타 / 아직 모르겠음 | 선물하는 30–40대 | 고객=선물 구매자(확인). 양조장은 공급 파트너 가정 | customer `needs_check`→부분 clear. 양조장을 고객으로 확정하지 않음 | 돈은 누가 내는가 (선물 수령자 ≠ 결제자 가능) | 고객과 양조장을 한 문장으로 섞어 확정 금지 |
| 3 | 술값을 실제로 내는 사람은 누구인가요? | `선물하는 사람이 냄` / `마시는 사람이 냄` / `양조장이 입점료를 냄` / 기타 / 아직 모르겠음 | 선물하는 사람이 냄 | 구매자=선물 구매자(확인). 입점 수수료는 별 수익 가정 | 구매자 확인. 양면 시장을 사실로 단정하지 않음 | 수익 비중이 판매인가 수수료인가 | |
| 4 | 매출은 어디서 더 나오나요? | `병 판매` / `양조장 수수료` / 기타 / 아직 모르겠음 | 기타 + `일단 병 판매가 먼저고 수수료는 나중` | 수익 우선순위=판매 먼저(확인). 수수료=후순위 가정 | solution `needs_check`. 「이미 팔린다」금지 | 지금은 어떻게 전통주를 사는가 | |
| 5 | 고객은 지금 전통주를 어떻게 사나요? | `대형마트·편의점` / `양조장 직접 방문` / `지인 추천` / 기타 / 아직 모르겠음 | 지인 추천 | 대안=지인·입소문(확인). 쿠팡을 지어내지 않음 | 차별 공백 | 발견을 지인보다 잘하게 하는 차이 | 문제를 재질문 금지 |

| 7 | 그 이유로 이미 산 사람이 있나요? | `결제·재구매 증거가 있다` / `아직 없다` / 기타 / 아직 모르겠음 | 아직 없다 | 검증 미실시 | 결론 HOLD. GO 금지 | 선물 구매자 5명에게 「지인 대신 여기서 고르겠는가」 | |
| 8 | 다음에 무엇을 확인하면 판단이 바뀌나요? | — | — | — | **종료:** HOLD. 고객·문제·구매자 확인. 차별·수요는 가설. 수수료 모델 미검증 | **다음 행동:** 이번 주 선물 예정자 5명에게 3개 양조장 묶음과 지인 추천을 비교하게 하고, 구매 의사만 기록 | 유통 계약이 있다는 식의 허위 사실 금지 |

**종료 불확실성:** 구색이 선물을 바꾸는지, 양조장 입점 의지, 반복 구매.

## S3 · B2B 업무 자동화 SaaS

**유형:** B2B SaaS · 증거 약함  
**초기 입력:**

```
서비스: 중소 제조사의 견적·발주 메일을 읽어 엑셀 발주서를 자동으로 채우는 툴
대상: 직원 20–80명 제조사 영업관리자
문제: 메일·엑셀·ERP에 같은 숫자를 세 번 옮기다 오타가 난다
수익: 좌석 월 구독
```

**시작 이해:** 가정만. 자동화 효과를 사실로 쓰지 않음.

| 턴 | AI 질문 | 선택지 | 창업자 | 이해 변화 | 판단 전→후 | 다음 | 금지 |
|---|---|---|---|---|---|---|---|
| 1 | 지금 가장 크게 줄이려는 실수는 무엇인가요? | `메일 숫자를 엑셀에 옮기다 나는 오타` / `ERP 중복 입력` / 기타 / 아직 모르겠음 | 메일 숫자를 엑셀에 옮기다 나는 오타 | 문제=전사 오타(확인) | problem `needs_check` | 누가 하루에도 이걸 하는가 | 전통주·배송 선택지 금지 |
| 2 | 이 툴을 매일 쓰는 사람은 누구인가요? | `영업관리자` / `대표가 직접` / `경리` / 기타 / 아직 모르겠음 | 영업관리자 | 사용자=영업관리자(확인) | customer `needs_check` | 구독료는 누가 결재하는가 | 사용자=결제자 가정 금지 |
| 3 | 월 구독료 결재자는 누구인가요? | `대표` / `영업팀장` / `관리부` / 기타 / 아직 모르겠음 | 대표 | 구매자=대표(확인). 사용자≠구매자 | 이중 슬롯 확인. 성급한 GO 금지 | 지금은 어떻게 옮기는가 | |

## 시나리오 종료 시 공통 기대

1. 결론이 GO이려면 고객·문제·구매자 확인 + 고객 변화를 지지하는 **외부 증거**가 있어야 한다. 위 6개는 모두 HOLD 또는 조건부다.
2. `아직 모르겠음`은 빈 칸을 유지하고 다른 공백으로 간다.
3. `기타`는 자유 입력을 가정으로 넣고 Fact로 올리지 않는다.
4. 확인된 슬롯(S1 문제, S4 정정 후 이전 고객)을 같은 의미로 다시 묻지 않는다.
5. 다음 행동은 사람·숫자·이번 주 단위여야 한다. 「더 조사하겠습니다」는 실패.

| R5 | 실제 UI 미검증 | 승인 후 UI에서도 동일 턴을 재현. E2E 미실행을 통과로 쓰지 않음 |

## CPO 검토 체크 (초안)

1. 질문이 그 사업의 핵심 불확실성을 겨냥하는가  
2. 선택지가 창업자 의사결정에 도움이 되는가  
3. 답 이후 이해·판단이 논리적으로 변하는가  
4. 확인된 사실을 다시 묻지 않는가  
5. 모르는 정보를 사실로 쓰지 않는가  
6. 다음 질문이 남은 불확실성에 근거하는가  
7. 마지막 판단·검증 계획이 대화 증거와 맞는가  

지적된 오류는 구현이 아니라 이 시나리오에서 먼저 고친다.

## CPO 검토 패키지 (기존 본문 요약)

S1–S6 턴 표가 본문이다. 여기서는 지식 구분, 반복 금지 근거, HOLD, 실행 결과만 모은다. 새 기능을 구현하지 않았다.

### 지식 구분 — 시작 / 종료

Fact = 창업자가 이 대화에서 확인한 것. Claim = 창업자 주장·정정. Assumption = 문서·미선택 항목. 미확인 = 묻지 않았거나 `아직 모르겠음`.

| 시나리오 | 시작 | 종료 Fact / Claim | 종료 Assumption | 종료 미확인 |
|---|---|---|---|---|
| S1 배송 SaaS | 전부 Assumption. Fact 없음 | 문제=주문·배송 분리. 고객=반찬가게. 수익=월 구독. 대안=분리 관리 | 꽃집도 고객일 수 있음. 한눈에 보기 효과 | 구매자. WTP. 시간 절감 증거 |
| S2 전통주 | 전부 Assumption. 사용자≠구매자 가능 | 문제=발견. 고객=선물 30–40대. 구매자=선물하는 사람. 수익 우선=병 판매. 대안=지인 | 양조장=공급. 수수료=후순위. 차별=구색 | 구색이 선물을 바꾸는지. 입점 의지. 재구매 |
| S3 견적 자동화 | 전부 Assumption | 문제=전사 오타. 사용자=영업관리자. 구매자=대표. 대안=수기 엑셀 | 손실=단가 오타(가설) | 빈도. 손실 금액. 대표 결재 의지 |
| S4 구독 박스 | 맞벌이 부모·선택 피로 Assumption | **정정 Claim:** 고객=20대 1인. 구매자 경로 불명. 문제=선택 피로(부모 맥락에서 온 것, 재평가 필요). 대안=쿠팡 | 차별=선택 제거 | 20대의 선택 피로·결제. 맞벌이 부모는 폐기 |
| S5 쿠키 D2C | 맛·가격은 창업자 주장 | 문제 주장=맛. 고객=헬스 20–30대. 대안=시중 바. 1회=지인 판매 | 차별=맛. 채널=트레이너 | 낯선 고객 재구매 |
| S6 중개 | 양면 Assumption | 우선 면=집. 문제=신뢰. 대안=지인. 구매자=집. 공급=없음. 결제=없음 | 차별=신원 확인 | 공급 확보. 수수료를 이길 신뢰 |

문서 문장은 시작에서 Fact가 아니다. 창업자 선택 후에만 Fact/Claim으로 올린다.

### 다음 질문 · 반복 금지 근거

| 시나리오 | 닫힌 슬롯 (다시 묻지 않음) | 다음을 고른 이유 |
|---|---|---|
| S1 | T1 문제 확인 후 문제를 「맞나요?」로 되묻지 않음 | 남은 핵심은 구매자. #197 현재는 여기가 실패(R1) |
| S2 | T1 문제 후 발견 불편을 재질문하지 않음 | 선물 맥락에서 사용자/구매자 분리가 더 큼 |
| S3 | T1–T3 문제·사용자·구매자 확인 후 동일 슬롯 금지 | T4 빈도는 규모. `아직 모르겠음`이어도 도구로 진행 |
| S4 | T7 이후 맞벌이 부모 선택지 재사용 금지 | T6 모순은 AI가 먼저 물은 재질문이 아니라 창업자가 뒤집은 입력. 그다음만 충돌 확인 |
| S5 | 문제·고객·대안 확인 후 맛 불만을 재질문하지 않음 | 남은 것은 증거의 강도 |
| S6 | 집 쪽 문제·대안·구매자 확인 후 재질문 금지 | 반대 면(공급)과 결제 증거가 비어 있음 |

S1 vs S2 vs S6 첫 질문·선택지는 주문·배송 / 전통주 발견 / 집 vs 도우미로 갈린다. 같은 일반 경영 질문이 아니다.

### HOLD 근거와 판단을 바꿀 증거

| 시나리오 | HOLD인 이유 | 판단을 바꿀 증거 |
|---|---|---|
| S1 | 구매자 모름. 고객 변화는 가설. 결제 없음 | 반찬가게 3곳이 시간 절감을 말하고, 누가 구독료를 내는지 확인 |
| S2 | 차별·수요 미검증. 수수료 모델 미검증 | 선물 예정자 5명이 지인 대신 묶음을 고름 |

| S4 | 고객이 한 번 뒤집힘. 새 고객의 결제 없음 | 20대 10명의 쿠팡 vs 박스 선택. 부모 메시지 폐기 |

### CPO 판단이 필요한 항목

1. S1 T2 다음을 구매자로 둘 것인가. 현재 구현은 문제 「맞나요?」로 돌아간다.
2. S4 T6은 창업자가 고객을 뒤집는 입력이다. AI가 먼저 고객을 다시 묻는 흐름으로 볼지, 자유 입력 모순으로 볼지.
3. S2 첫 선택지에서 「양조장 채널 부재」를 넣을지. 창업자가 발견 문제를 고르면 양조장은 가정으로 남는 것이 맞는가.
4. 6개 HOLD와 검증 행동이 충분한가, 더 일찍 종료해야 하는가.
5. 실패 R1–R4를 시나리오 수정으로 고칠지, 승인 후 코드 수정 대상으로 남을지.

구현은 정지 상태다. 위 항목은 시나리오 단계에서 먼저 판정한다.
