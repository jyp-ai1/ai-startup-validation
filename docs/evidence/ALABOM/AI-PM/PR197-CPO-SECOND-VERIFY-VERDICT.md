## 3. 시나리오별 CPO 메모 (CTO 표의 재진술이 아님)

### 확인한 진전

- **R1:** 실제 nextQ = `이 문제를 해결할 때, 실제로 비용을 지불하거나 도입을 결정하는 사람은 누구인가요?` 닫힌 문제 confirm이 아니다.
- **R2:** 같은 결론 문장이어도 customerChange reason이 `약증거` vs `미확정`으로 갈린다. 질문이 바뀌고 판단 근거도 바뀐다.
- **R4:** 전통주 대안 라벨이 발견 우회 행동이다. 문제 문장 재사용 없음.
- **선택지 절단:** S3 문제=`메일·엑셀·ERP에 같은 숫자를 세 번 옮기다 오타가 난다`. S2 고객=`전통주를 선물·취미로 찾는 30–40대`.
- **S4 다음 질문:** 모순 입력 후 `어느 쪽이 지금 맞는 고객인가요?` — 질문 층은 맞다.

### 실패로 보는 것

1. **S6 대화 중단** — 양면 시장인데 집이 고객인 것만 확인하고 공급·신뢰 가설로 못 간다. CPO 7항 실패.
2. **S4 판단 미갱신** — gapState는 CONTRADICTED인데 judgment.customer = `맞벌이 부모` / `ceo_confirmed`. 상태가 바뀌어도 Founder가 보는 판단이 안 바뀌면 실패다.
3. **문서 한 줄 후퇴** — S2–S5에서 구매자를 닫은 뒤 `이 사업은 누구에게 무엇을 제공하나요?`가 다시 나온다. 이미 문서에 있는 한 줄은 미해결 핵심 가설이 아니다.

### 실행하지 않은 것 (완료 아님)

- S4 T7: 20대를 고른 뒤 부모/아이가 superseded 인지는 덤프에 없다.
- 로그인 UI 8턴.
- 동결 시나리오 T1–T8 문구 일치.

## 6. CEO 보고 가능 문장

이번 주 엔진은 고객 답 다음에 닫힌 문제를 되묻지 않고, 결제 증거 유무가 판단 근거를 가른다. GO를 증거 없이 말하지 않는다.
