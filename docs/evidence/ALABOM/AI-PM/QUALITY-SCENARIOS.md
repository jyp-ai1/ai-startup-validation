# 양조장 AI 질의 품질 평가

코드 커밋 `98e73993d4ec25a0e9e3914ccaa0b9cecbec866a`. 이 문서는 그 다음 커밋이다. 둘 다 Preview 런타임 SHA가 아니다.

1차 게이트는 FAIL이다. Production `0b465226516e1a4f3eb9ce2087f8bca2c2c091da`는 잠금이다. PR #209는 병합하지 않는다. 제품의 `POST /api/ai-pm-review/follow-up`과 피드백 저장 API는 이 평가에서 호출하지 않았다. UI는 바꾸지 않았다.

## 실행 명령

| 명령 | 이 실행 |
|---|---|
| `pnpm --filter web test:ai-pm-quality` | 실행함. 7건 통과. 모델 호출 없음 |
| `pnpm --filter web test:ai-pm-quality-live` | **NOT RUN**. `AI_PM_QUALITY_LIVE=1`과 `GPT_API_KEY`가 없다 |

라이브 명령은 `apps/web/features/business-validation-journey/lib/__tests__/ai-pm-quality-scenarios.live.test.ts`를 연다. 키가 있으면 `executeQualityMatrix`가 기준 S1, 현재 S1, S2–S8을 독립 호출하고 `docs/evidence/ALABOM/AI-PM/quality-scenario-live.json`에 원문을 남긴다. 그 파일은 없다. 키가 없는 라이브 실행은 품질 PASS를 쓰지 않고 `NOT RUN`만 남기도록 되어 있다. 이번 실행은 그 파일도 쓰지 않았다.

평가 코드는 `apps/web/features/business-validation-journey/lib/ai-pm-quality-scenarios.ts`다. 제품 follow-up 라우트는 이 모듈을 import하지 않는다.

## 평가 기준 `rubric-2`

각 항목은 PASS, FAIL, 또는 평가하지 않음(`not_run`)과 응답 인용을 남긴다. 의미 항목은 문자열 검색으로 PASS하지 않는다.

| 항목 | 종류 | 이 스크립트가 하는 일 |
|---|---|---|
| `business_understanding` | 의미 | 항상 `not_run` |
| `analysis_coverage` | 의미 | 항상 `not_run` |
| `assumption_quality` | 의미 | 항상 `not_run` |
| `question_quality` | 의미 | 항상 `not_run` |
| `fact_grounding` | 기계 | 확정 단정, 원문에 없는 억·만 단위, 비hedge 수수료·참가비 |
| `choice_quality` | 기계 | 선택지 3–5개와 직접 입력. 실패 A가 있으면 FAIL |
| `next_step_quality` | 기계 | 실험, 파일럿, 확인, 제안, 인터뷰 중 하나의 존재. 문장 품질은 보지 않는다 |
| `context_retention` | 기계 | S1은 이전 답이 없어 `not_run`. S2–S8은 이전 질문 반복과 창업자 답 앞 12자의 존재 |
| `regression_A` | 기계 | 협력 가능성을 높다/낮다/미정에 고착하면 FAIL |
| `regression_B` | 기계 | 원문에 없는 수수료·참가비·체험 참가비를 hedge 없이 쓰면 FAIL |

전체 판정은 오류나 항목 FAIL이 하나라도 있으면 FAIL이다. 다른 항목의 PASS로 상쇄하지 않는다. 의미 항목이 `not_run`이면 전체도 `not_run`이다. 따라서 이 스크립트는 의미 품질 PASS를 내지 않는다. `source: not_called`인 `not_run`은 모델 미호출이다. `source: model`인 `not_run`은 응답은 있으나 의미 평가를 하지 않은 상태다.

`regression_B`의 hedge는 각 등장 위치의 앞뒤 40자 안에 `가설`, `제안`, `확인되지`, `원문에 없`, `단정하지`, `모르`, `미정`, `아직`, `의사`, `주장`이 있는 경우다. 한 번이라도 그 창에 없으면 FAIL이다. S6이 창업자 문장 “수수료, 체험 참가비, 마케팅 서비스 비용 중 무엇이 적절한지 아직 모른다.”를 인용하면 기계 규칙은 PASS다. 저장된 문장 “수익 구조는 양조장으로부터의 수수료 및 체험 참가비.”는 FAIL이다.

## 고정 시나리오

입력 원문은 아래 양조장 본문이다. 하니스는 본문만 보낸다. 제품 화면은 제출 시 `검토 목적: 종합 사업성 검토`, `현재 단계: 미확인`, `가장 알고 싶은 것: 없음`, `검토 계약: comprehensive-1`을 붙인다. 이번 라이브 비교는 그 봉투로 호출하지 않았고, 본문으로도 호출하지 않았다.

다양한 관광객이 늘며, 개인별 다양한 경험을 중요시 한다. 우리는 개인별 다양한 경험을 중요시하는 관광객 중 전통주와 양조장을 좋아하는 내국인·외국인을 대상으로 양조장 체험을 안내하고, 주변을 즐길 수 있는 사업을 구상 중이다. 이 사업은 양조장의 다양한 온라인 마케팅에서 시행될 수 있어서 이를 지원하려 한다. 위 내용으로 사업성 검토와 추가 질의가 필요한 부분을 안내해 달라.

| ID | 창업자 답 | 기대 | 금지 |
|---|---|---|---|
| S1 | 없음. 최초 분석 | 고객, 문제, 가치, 차별점, 수익 가설, 시장·운영 리스크, 핵심 가정, 저비용 검증, 그 가정에서 나온 첫 질문 | 협력 가능성을 높다/낮다로만 묻기. 원문에 없는 수수료·참가비를 사실로 쓰기 |
| S2 | 아직 협력 양조장이 없다. | 공급 확보와 파일럿 가능성을 우선한다 | 제휴 가능성을 높음/낮음으로만 다시 묻기. 제휴 확정 |
| S3 | 양조장 3곳이 참여 의사를 밝혔다. | 참여 의사와 확정 계약, 실제 체험 제공을 구분한다 | 3곳 참여를 검증된 공급으로 쓰기 |
| S4 | 관심은 있을 것 같지만 실제 유료 고객은 없다. | 관심과 지불 의사를 나누고 저비용 유료 실험을 제안한다 | 유료 고객이 이미 있다고 쓰기 |
| S5 | 외국인 개별 관광객을 우선 고객으로 생각한다. | 언어, 예약 접근성, 이동, 체험 이해도, 고객 획득 경로를 가설로 본다 | 외국인 수요가 확인된 사실이라고 쓰기 |
| S6 | 수수료, 체험 참가비, 마케팅 서비스 비용 중 무엇이 적절한지 아직 모른다. | 수익 후보를 가설로 나누고 누가 무엇에 지불할지 검증하게 한다 | 수수료나 참가비를 기존 사실로 단정하기 |
| S7 | 양조장들은 마케팅 비용을 지불할 의사가 없다고 답했다. | 기존 수익 가설을 재검토하고 관광객 지불, 공공·지역 파트너십을 가설로 비교한다 | 대안 수익이 이미 확보된 것처럼 쓰기 |
| S8 | 관광객 수요는 있을 것 같지만 공급과 운영 가능성은 아직 확인하지 못했다. | 수요와 공급·운영을 별도 가정으로 나누고 더 위험한 가정부터 검증한다 | 양쪽이 확인된 사실이라고 쓰기 |

S2–S8의 이전 분석은 같은 러너가 받은 현재 프롬프트 S1의 `summary`와 `nextQuestion`이다. 제품 후속 검토 경로는 쓰지 않는다. S1 JSON에 그 두 필드가 없으면 해당 턴은 `previous_analysis_missing`이며 모델 품질 PASS가 아니다.

## 프롬프트

`quality-1`은 `BASELINE_FIRST_SYSTEM_PROMPT`에 고정했다. 제품 라우트는 이 문자열을 호출하지 않는다. `buildBaselineFirstRequest`만 사용한다.

`quality-2`는 제품 `buildFirstReviewRequest` / `firstReviewSystemPrompt`다. `quality-1`과의 차이는 앞부분 두 문장이다.

- `프롬프트 버전 quality-2.`를 붙인다.
- `창업자가 아직 고르지 않은 답을 사실로 만들지 않는다. 첫 질문은 정도(높다, 낮다)가 아니라 사업의 갈림길을 가른다.`를 붙인다.

나머지 문장(사실·추론·가설 구분, 수익을 가설로 적기, 정도만 다른 선택지 금지, JSON 키)은 같다. 이 차이는 `6b9994a4`에서 들어갔고, 그 전에 기준 프롬프트의 실제 S1 응답을 수집하지 못했다. 이번 실행도 제품 프롬프트를 다시 고치지 않았다. 지시서의 “기준 응답을 본 뒤 최소 수정” 단계는 **NOT RUN**이다.

S2–S8 시스템 문장은 `scenario-sim-1`이다. 첫 문장은 `이 요청은 품질 시뮬레이션이다. 제품의 후속 검토 경로가 아니다.`다. `buildFollowUpRequest`에는 이 문장이 없다. 시뮬레이션 상한은 1400토큰이고 제품 후속 상한 800토큰과 다르다.

| 항목 | 판정 |
|---|---|
| `quality-1` S1 원문 | **NOT RUN** |
| `quality-2` S1 원문 | **NOT RUN** |

| 반복 실행과 분산 | **NOT RUN**. 키가 없어 호출하지 않음 |
| 저장된 실패 A 문자열의 기계 재채점 | FAIL. `regression_A`. 새 모델 응답이 아니다 |
| 저장된 실패 B 문자열의 기계 재채점 | FAIL. `regression_B`. 다른 항목 PASS로 상쇄되지 않는다 |
| 의미 항목 4개 | `not_run`. 문자열 검색으로 통과시키지 않음 |
| 주입 채팅 행렬 | 테스트가 9회 호출을 `injected_chat`으로 기록한다. 모델 PASS가 아니다 |

| 전체 회귀 통과 | 선언하지 않음 |

이전에 화면에 남았던 질문 `양조장과의 협력 가능성은 어떻게 되는가?`와 수익 문장 `수익 구조는 양조장으로부터의 수수료 및 체험 참가비.`는 기계 규칙에서 다시 FAIL이다. 그 응답의 런타임은 `a022a72f`이고 모델은 `gpt-4o-mini-2024-07-18`이었다. `quality-2`의 새 응답은 아니다.

## 잔여 위험

- 의미 품질 4항목은 사람이 원문을 읽기 전에는 비어 있다.
- `next_step_quality`는 확인류 단어의 존재만 본다. 저비용 실험인지는 보지 않는다.
- `context_retention`은 창업자 답 앞 12자와 이전 질문 문자열만 본다.
- hedge 창 40자는 S6 인용을 살리기 위한 규칙이다. 창 안에서 우연히 겹치는 단어가 있으면 기계 규칙은 PASS할 수 있다. 그때도 의미 항목은 `not_run`이다.
- 제품 파서는 정도만 다른 선택지를 여전히 저장한다. 거부는 하니스 채점이다. 파서가 거부하면 같은 입력 해시가 다음 클릭에서 모델을 다시 부르기 때문이다.
- 하니스 본문과 제품 화면의 검토 계약 줄은 다르다. 라이브 비교 때 어느 쪽을 보냈는지 원문에 남겨야 한다.
