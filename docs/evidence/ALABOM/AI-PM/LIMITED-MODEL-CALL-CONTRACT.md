# 제한된 Gemini·GPT 호출 계약

상태: CPO 검토용 설계. 이 문서는 모델 호출을 승인하지 않는다.
기준: Production 잠금 SHA `0b465226`. PR #198. 보고 커밋 `098468bd` 다음.
범위: 실행·근거·판단 계약, 비용·개인정보 경계, 호출 전 체크리스트, 검증 계획.
하지 않은 일: Gemini HTTP, 유료 GPT, API 키 추가, 자동 재시도, 원장의 요청 경로·화면 연결, 프로덕션 DB 변경, 병합, 배포.

상태 단어는 아래 뜻으로만 쓴다.

| 상태 | 뜻 |
| --- | --- |
| 확인됨 | 이 브랜치의 순수 함수 또는 로컬 SQLite 프로세스 재시작이 그 규칙을 잠근다. 배포 서버나 실제 모델의 증거가 아니다. |
| 설계안 | 다음 호출 전에 지키기로 이 문서가 정한다. 요청 경로와 화면에는 없다. |
| 미검증 | 실제 모델 응답, 배포된 서버의 재시작, 요금표, 약관, 공개된 삭제 기한, 사업 판단의 정확도. |

픽스처가 통과해도 모델 품질이나 사업 판단 정확도의 증거가 아니다.

## 1. 실행 상태 전이와 불변조건

코드: `execution-ledger.ts`, `ledger-recovery.ts`, `ledger-disk-store.ts`.

| 현재 | 다음 | 조건 | 상태 |
| --- | --- | --- | --- |

| `in_progress` | `failed` | 제공자 오류 사유가 있다. 응답 본문으로 덮지 않는다. | 확인됨 |

| `in_progress` | `response_received` | 같은 `executionId`의 응답 본문. 다른 실행의 응답은 거절. | 확인됨 |

| 규칙 | 상태 |

| 비용 계수는 `networkCalled=true`인 기록만 센다. 미확정 전송을 비용 0으로 단정하지 않는다. | 확인됨 |

| 저장이 실패하거나 커밋 전에 프로세스가 죽으면 성공 phase와 여정 상태 변경을 확정하지 않는다. | 확인됨 |

| 위 규칙이 배포된 서버의 재시작에서도 유지된다. | 미검증 |
| 이 원장이 제품 화면이나 요청 경로에 연결되어 분석 결과와 복구 상태를 보여 준다. | 미검증. 이번 단계에서는 연결하지 않는다. |

## 3. 근거 충돌과 판단 변경

분리. 코드: `citation-reconciliation.ts`, `cross-review-contract.ts`, `analysis-acceptance.ts`.

| 규칙 | 상태 |
| --- | --- |
| 창업자 원문, Gemini 분석, GPT 반대 검토는 출처 필드가 따로 있다. | 확인됨 |
| 모델이 인용한 문구와 저장된 원문은 다른 필드다. | 확인됨 |
| 인용 일치(`matched` / `mismatched` / `uncheckable`)와 주장의 근거 충족(`grounded` / `ungrounded` / `unassessed`)은 다른 축이다. | 확인됨 |
| 발췌가 원문에 없어도 주장을 반대 사실로 뒤집지 않는다. | 확인됨 |
| 발췌가 원문과 맞아도 주장이 그 문장 밖이면 `ungrounded`다. `verifiedFact`는 false다. | 확인됨 |
| 두 모델의 문장이 같아도 `verifiedFact`는 false다. 합의는 사실 검증이 아니다. | 확인됨 |
| 결론이 다르면 `disagreement`다. 양쪽 주장을 남기고 한쪽을 지우거나 최신 결과로 덮지 않는다. | 확인됨 |
| 한쪽이 없거나 실패하거나 결과가 없으면 `not_compared`다. 비교하지 않은 상태를 합의로 보지 않는다. | 확인됨 |
| 출처나 주장이 없으면 `insufficient_evidence`이고 이전 판단을 유지한다. | 확인됨 |
| 모델 수용 기록의 `judgmentChanged`는 false다. `previousJudgmentText`와 `nextJudgmentText`는 같다. 가설 `changed`도 false다. | 확인됨 |
| 근거가 부족하면 판단 유보다. 유보된 가설에는 다음 검증 행동이 있다. 충돌이면 업무 절차 관찰 원문 한 줄이다. | 확인됨. 여정 상태 픽스처. 실제 모델의 불확실성이 그 행동을 고른 증거는 아니다. |
| 창업자 원문 전이는 원인 ID가 있을 때만 가설 stance를 바꾼다. 지불 의사, 구매, 반복 사용, 확장은 그 원문만으로 확정하지 않는다. | 확인됨. 창업자 원문 픽스처이며 모델 품질이 아니다. |
| 모델 분석이 사업 판단 문장을 바꾸는 경로. | 미검증. 구현하지 않았다. |

판단 문장을 바꾸는 호출은 이번 설계에서 열지 않는다. 나중에 열려면 한 기록에 이전 판단 문장, 변경 사유, 영향받은 가설 ID, 관련 근거 ID가 있어야 한다. 그 넷 중 하나라도 없으면 유보를 유지한다. 이 조건은 설계안이다. `verifiedFact`는 그 경우에도 false다.

시나리오.

| ID | 상황 | 기대 | 상태 |
| --- | --- | --- | --- |
| S1 | 두 주장이 같고 발췌가 저장된 원문 안에 있으며 주장도 그 발췌 안에 있다 | 합의, `matched`, `grounded`. 사실은 아니다. 판단 문장은 유지 | 확인됨 |
| S2 | 두 주장이 같고 원문 ID나 발췌가 없다 | `insufficient_evidence`. 판단 유지 | 확인됨 |
| S3 | 두 주장이 다르다 | `disagreement`. 양쪽 보존. 어느 쪽도 사실이 아니다. 추가 원문 한 건이 다음 증거 | 확인됨 |
| S4 | 발췌가 저장된 원문에 없다 | `mismatched`. 주장을 반대로 바꾸지 않음 | 확인됨 |
| S5 | 발췌는 맞지만 주장이 지불·구매·반복·확장이다 | `ungrounded`. 사업성 입증이 아님 | 확인됨 |
| S6 | 같은 실행 ID의 실패 뒤에 성공 본문이 온다 | 접힌 phase는 `failed`. 첫 실패 유지 | 확인됨 |
| S7 | 모델 문장만으로 판단 문장을 바꾼다 | 하지 않음 | 설계안 |
| S8 | 실제 Gemini와 GPT가 S1–S5처럼 가설을 지지하거나 반박한다 | 추적 가능해야 한다 | 미검증 |

| 4 | `networkCalled`는 전송 기록 후에만 true다 | 설계안. 기록 함수는 있으나 전송 코드는 없다 |
| 5 | 미확정은 재호출하지 않고, 비용 0으로 단정하지 않는다 | 확인됨 |
| 6 | 단가, 무료 한도, 약관을 확인하기 전에는 `priceStatus=unconfirmed`다 | 미검증 |
| 7 | 삭제 기한을 약속하지 않는다 | 설계안 |
| 8 | 실행 ID, 가설 ID, 원문 ID, 모델 발췌, 저장된 원문이 한 수용 기록에서 추적된다 | 확인됨. 픽스처 |
| 9 | 합의, 출처 일치, `grounded`가 `verifiedFact`를 true로 만들지 않는다 | 확인됨 |
| 10 | 상충 주장은 둘 다 남는다 | 확인됨 |
| 11 | 판단 문장 변경은 이전 문장, 사유, 가설 ID, 근거 ID가 있을 때만 한다 | 설계안. 모델 경로는 변경하지 않음 |
| 12 | 불확실하면 유보하고, 다음 행동은 그 가설의 부족한 원문을 가리킨다 | 확인됨. 여정 픽스처. 실제 모델은 미검증 |
| 13 | 원장을 화면과 요청 경로에 연결하는 일은 별도 승인이다 | 설계안. 현재 연결하지 않음 |
| 14 | Production SHA `0b465226`을 유지한다 | 확인됨. 이번 커밋도 배포하지 않음 |

## 7. 검증 방법과 미검증

| 산출물 | 이미 잠근 방법 | 아직 아닌 것 |
| --- | --- | --- |
| 전이표 | `execution-ledger`, `ledger-recovery`, `ledger-disk-restart` 픽스처와 로컬 프로세스 재시작 | 배포 서버 재시작. 화면의 복구 상태 |
| 입출력 계약 | 패킷 필드와 상태 구분 픽스처. 키 없음 게이트 | 실제 요청과 응답. 프롬프트. 모델이 필드를 지키는지 |
| 근거와 판단 | 교차 검토, 출처 대조, 수용 기록 픽스처 | 실제 분석이 가설을 어떻게 바꾸는지. 그 변화가 근거로 정당화되는지 |
| 비용과 재시도 | 원장 상한, `retry_refused`, 비용 계수가 전송 기록만 셈 | 게시 단가, 약관, 실제 청구 |
| 개인정보 | 공개 문장에 기한이 없음을 대조. 로그에 본문이 없는 재시작 워커 | 정책 승인. 삭제 구현. 프로덕션 접근 통제 |
| 호출 전 체크리스트 | 이 문서의 표 | 체크리스트 통과를 호출 허가로 읽는 일 |

다음 검토에서 볼 기준은 테스트 개수가 아니다. 각 모델의 분석이 어느 가설을 지지하거나 반박했는지, 그 변화가 어느 원문과 어느 실행 ID에 묶이는지, 불확실할 때 다음 검증 행동이 그 빈칸을 가리키는지다. 그 기준은 실제 호출 전에는 미검증이다.
