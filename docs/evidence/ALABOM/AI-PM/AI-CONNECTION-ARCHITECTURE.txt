열지 않은 곳: chatgpt.com, claude.ai, gemini 웹, Chrome LanguageModel, 로컬 모델, OpenAI API, Gemini API, OpenRouter, Anthropic API.
따라서 성공률, 세션 만료율, 응답 완료 판정, 중복 수집률은 실측값이 없다. 로컬 붙여넣기 성공을 이 성공률에 넣지 않는다.

5. 판단 품질과 UX

품질: 모델이 문제 가설, 지불자 가설, 다음 검증을 어떻게 바꾸는지 실측하지 않았다. 붙여넣은 문장은 judgmentChanged false, verifiedFact false 다. Gemini 와 GPT 의 동의로 가설을 검증 처리하는 분기는 없다.
바뀐 것: 다음 질문 ID, 다음 행동 문장, 다음 분석 입력에 포함된 창업자 답과 실행 ID.
바뀌지 않은 것: 판단 문장, 판단 상태 judgment_deferred, 가설 판단 참조.
UX: 로컬에서 센 손동작은 필드 입력, 이해 확인, 문장 붙여넣기, 참고 보관, 객관식과 주관식 답, 고객 수정이다. AI 웹에서의 대기와 복사 실패는 재지 않았다. 확장 설치 단계는 없다. 그 설치를 생략한 이유는 편의가 아니라 A 경로를 열지 않기 위해서다.

6. 비용, 보안, 운영

- 이번 PoC 의 모델 API 청구는 0 이다. 확장 유지보수비도 0 에 가깝다. 확장을 만들지 않았기 때문이다. 사용자가 실제 AI 를 쓰려면 그 서비스 구독이나 대기 시간이 들 수 있다. 그 금액은 측정하지 않았다.
- C 를 나중에 쓰면 API 청구는 0 에 가깝더라도 모델 다운로드와 미지원 언어가 비용이다. 한국어는 게시 목록에 없다.
- D 를 나중에 쓰면 설치 용량과 메모리가 비용이다. 이 머신의 가용 메모리로는 내려받지 않았다.
- 붙여넣은 문장과 창업자 답은 이 출처의 sessionStorage 에 남는다. 퍼널 이벤트 validation_journey_handoff_kept 는 화면, research_not_run, question_id, category reference 만 보낸다. 원문은 이벤트에 넣지 않았다.
- 사용자가 제3자 AI 에 사업 문장을 직접 넣으면 그 보관은 그 서비스의 정책이다. ALABOM 이 대신 보내지 않았다. 그 노출을 이번 테스트로 측정하지 않았다.
- 쿠키, 인증정보, API 키를 저장하거나 로그에 남기지 않았다.
- 분석 실패 시 이전 판단을 덮어쓰지 않는다. 빈 입력과 실패 플래그가 그 경로다.
- 운영 리스크: 사용자는 모델 문장을 사실로 오해할 수 있다. 화면은 "사실 아님" 과 "검증된 사실이 아니다" 를 같이 보여 준다. 모델 품질 리스크는 아직 측정 전이다.

7. 선택 이유

A 를 고르지 않는다. 허용 범위가 확인되지 않았고, 실왕복 증거가 없으며, 화면 변경에 유지보수가 묶인다.
C 를 고르지 않는다. 이 Chrome 에 API 가 없고, 메모리가 문서의 CPU 기준보다 낮고, 한국어가 게시 언어가 아니다. 창업자 PC 에서는 다를 수 있다. 그 확인 전에는 확정하지 않는다.
D 를 고르지 않는다. 런타임이 없고 품질 테스트가 없다.
E1 은 B 의 입력 수단이다. 별도 수집기를 만들지 않는다.
E3 은 외부 분석을 대체하지 않는다. 판단 주인으로 남긴다.
B 를 지금 허용된 구현으로 둔다. 실모델 문장이 돌아온 것이 아니므로, 사업 판단이 연결되었다는 결론은 아니다.

8. 구현한 범위와 아닌 범위

구현
- apps/web/features/business-validation-journey/lib/external-handoff.ts
- 화면 패널. 준비 문장, 실행 ID, 붙여넣기, 참고 기록, 다음 입력.
- 답변과 고객 수정 뒤에도 참고가 남음.
- 퍼널 이벤트 이름 validation_journey_handoff_kept. 원문 미포함.

하지 않음
- Chrome 확장, 콘텐츠 스크립트, 호스트 권한.
- 실제 AI 왕복, 브라우저 내장 모델 호출, 로컬 모델 설치.
- 공식 API 호출과 키.
- 판단 문장을 새 답변으로 갱신하는 일. 계약상 참고 문장과 미실행 조사로 검증 처리하지 않는다.
- 원장 화면 연결, 프로덕션 DB, 병합, 배포.
- 자동 재시도, 대량 실행, 쿠키 추출.

9. 다음 작업

아키텍처 확정 전에는 A, C, D, 공식 API 를 구현하지 않는다.
확정 뒤에도 실왕복은 사용자가 자기 세션에서 얻은 문장을 가져오는 범위에서만 시작할 수 있다. ALABOM 이 그 페이지를 대신 열거나 키로 호출하는 작업은 별도 지시다.
그 전에 손볼 수 있는 허용 범위는 복사 버튼처럼 AI 페이지를 읽지 않는 조작뿐이다. 이번 제출에는 넣지 않았다. 왕복 증거를 늘리지 않기 때문이다.
CPO 가 볼 빈칸은 세 가지다. 실제 모델 문장이 실행 ID 와 함께 돌아왔는가. 그 문장이 아니라 창업자의 새 답이 다음 입력에 남고 판단 변경 이유가 갈라져 기록되는가. 실패 때 이전 판단이 남는가. 지금은 두 번째의 입력 보존과 세 번째만 로컬에서 확인했다. 첫 번째는 시도하지 않았다.
