1. 연결

present-workspace-judgment.ts 가 JudgmentLedger.judgment 와 DecisionRecord.prompt 를 WorkspaceJudgmentView 로 투영한다. 판단을 다시 계산하지 않는다. 가설 id 는 화면 라벨로 바꾸고, binding id 와 불확실성 id, 후보 id, targetGap, tieBreak, score 는 뺀다.
classify-founder-event.ts 가 아홉 이벤트와 거절만 엔진에 전달한다. 분류되지 않으면 직전 ledger 와 prompt 를 유지한다. 창업자 문장을 VALIDATED 로 올리지 않는다. 문자 기록만 기존 bindLiteralFact 로 FACT 가 되고, 귀속은 unreviewed, 진위는 false 다.
빈 문제 칸을 엔진이 묻고 있을 때의 문제 문장은 기존 affirm 으로 그 칸에 들어간다. 결제 주체 확인은 아홉 이벤트에 없으므로 거절하고 직전 판단을 유지한다.
workspace-ai-pm-main.tsx 의 판단 문장과 다음 행동은 그 뷰에서만 그린다. isPostReview 로 숨기지 않는다. 문서 분석기 판단을 같이 그리지 않는다. ledger 가 있는 동안 이해 확인 카드의 별도 질문을 그리지 않는다.
workspace-ai-pm-loop-panel.tsx 는 siValidationAsk 로 질문 문장을 덮지 않는다. ledger 답은 분류 어댑터로만 가고, 그 동안 루프의 질문 문장과 CEO 판단 문장을 그리지 않는다.

4. 브라우저

로컬 http://127.0.0.1:3000 의 데모 워크스페이스만 열었다. Preview 가 아니고 Production 이 아니다. 새 배포를 만들지 않았다.
판단 문장 노드 1, 다음 행동 노드 1, 기존 si-review-surface 0 이었다. 「이 이해가 맞습니까」와 「AI가 이해한 내용」은 보이지 않았다.
문제 문장 「배차 기준이 현장에 없다」를 보낸 뒤 판단은 CLAIM 으로 바뀌었고 VALIDATED 는 아니었다. 다음 행동은 그 시점 엔진 prompt 「핵심 불확실성 없음을 닫는 후보가 없다. 필요한 증거는 추가 근거다.」였다.
A부터 E 를 이 브라우저에서 재현하지 않았다. 데모 샘플 카드는 사업 설명을 옆에 계속 보여 준다. 그것은 S.I. 판단 노드가 아니다.
배포된 Preview 는 이번 SHA 를 서빙하지 않는다. 이전 Preview 는 Vercel SSO 뒤였고, 우회하지 않았다. A–E 의 Preview 화면 일치는 미검증이다.
