2. 반복 루프 상태 전이

상태는 구현 파일의 enum 이 아니다. 의미와 전이만 고정한다.

research_not_run
- URL 이 없거나, 브라우저 함수를 호출하지 않았거나, 호출 전에 끝났다.
- 모델이 조사했다는 문장만으로는 이 상태에서 나가지 않는다.

research_completed
- 이번 바퀴의 캡처에 requestedUrl, finalUrl, http status, title, excerpt, collectedAt 이 있고 error 가 없다.
- 같은 url 과 같은 excerpt 해시가 이전 바퀴에 있으면 새 조사 완료가 아니다. 이전 캡처를 가리킨다.

counter_review_completed
- Gemini 요청과 다른 두 번째 HTTP 요청이 있고, 그 요청 model 이 GPT 카탈로그 id 이며, 응답 원문이 저장되었다.
- 두 번째 호출이 google/gemini-2.5-flash 이면 이 상태에 들어가지 않는다. 현재 연구 코드는 이 상태에 도달하지 못한다. 미완성이다.

synthesis_pending
- 한쪽 역할의 원문이 없거나, 주장의 근거 id 가 캡처나 창업자 원문에 연결되지 않았거나, 충돌 목록을 만들기 전이다.
- 이 상태에서 판단을 제공하지 않는다.

judgment_provisional
- 잠정 판단 문장이 있고, 각 문장의 근거 id 가 page_record 또는 observed_outcome 또는 founder_claim 이다.
- founder_claim 만 있으면 이 상태가 아니다.
- 직전 판단과 본문이 다르면 changeCauseIds 가 비어 있으면 이 상태로 저장하지 않는다.

judgment_deferred
- 독립 근거가 부족하다. 미확인과 다음 검증이 있다.
- 조사 완료도 판단 완료도 아니다.

reentry_required
- 새 캡처 해시, 새 founder_claim, 새 observed_outcome, 또는 changeCauseIds 가 있는 판단 본문 변경이 있다.
- 다음 바퀴의 Gemini 와 GPT 입력이 된다. 직전 판단 원문은 유지한다.

loop_budget_held
- 바퀴 수가 4 에 닿았거나, 승인된 금액 한도에 닿았다.
- 직전 판단을 유지한다. 사업 검증의 성공도 실패도 아니다. 추가 모델 호출을 하지 않는다.

전이.
- 시작과 URL 없음 → research_not_run → 모델이 질문만 내면 synthesis_pending 을 거치지 않고 judgment_deferred.
- URL 있고 캡처 성공 → research_completed. GPT 독립 호출이 없으면 counter_review_completed 로 가지 않고 synthesis_pending 에 머문다. 판단은 judgment_deferred.
- 캡처 성공과 GPT 독립 호출 성공 → counter_review_completed. 근거가 연결되면 judgment_provisional 또는, 고객 행동이 없으면 judgment_deferred.
- 새 근거 또는 원인 있는 변경 → reentry_required → 다음 바퀴의 research 단계. 이전 기록은 삭제하지 않는다.
- 브라우저 실패나 모델 실패 → 직전 상태와 직전 판단을 유지하고 error 를 추가한다. research_completed 나 counter_review_completed 로 올리지 않는다.
- 4바퀴 → loop_budget_held. 그 전에 독립 근거가 있으면 마지막 provisional 을 보여 주되 성공으로 세지 않는다. 없으면 deferred 를 유지한다.

3. 근거·충돌·판단 변경 계약

LoopRoundRecord. 구현 타입이 아니다.

- inputRevisionId, conversationTurnIds: 원본 입력과 대화 id. 본문을 복사해 둔다.
- captures: requestedUrl, finalUrl, status, title, excerpt, excerptHash, collectedAt, error.
- geminiCall: modelId, endpoint, requestBody, responseBody, error. 호출하지 않았으면 null.
- gptCall: modelId, endpoint, requestBody, responseBody, error. 독립 호출이 아니면 null. 이름만 openai 인 연구 공급자 결과는 여기에 넣지 않는다.
- claims: claimId, text, grade, sourceId, excerptStart, excerptEnd.
- conflicts: conflictId, claimIdA, claimIdB, unresolved.
- provisional: text, previousHash, nextHash, changeCauseIds.
- nextAction: uncertaintyId, text, reason, kind.
- execution: attempted, status, failureReason.

grade 는 founder_claim, page_record, model_inference, observed_outcome 만 둔다.
model_inference 는 캡처 excerpt 안에 없는 문장이다. page_record 로 올리지 않는다.
excerptHash 가 이전과 같으면 새 근거 수에 넣지 않는다. sourceId 는 처음 캡처 id 를 재사용한다.
changeCauseIds 가 비어 있는 본문 변경은 저장하지 않는다. previousHash 의 판단을 유지한다.
두 모델의 같은 문장은 grade 를 바꾸지 않는다.

4. 시나리오 A–J

공통 입력의 사업 주장은 배송 소상공인, 주문과 배송을 따로 관리, 월 구독이다. 성패를 알고 있다고 말하지 않는다. 아래는 기대 전이다. 화면과 모델로 실행하지 않았다.

A. 사업 정보만 있고 URL 이 없다.
- 입력: 위 주장. allowedUrls 빈 배열.
- 기대: research_not_run, judgment_deferred.
- 보존: 창업자 원문. 캡처 없음. geminiCall 과 gptCall 은 null 이거나, 질문을 만들기 위해 호출했다면 그 원문만 있고 조사 완료가 아니다.
- 다음 행동: 공개 URL 또는 관찰 기록을 하나만 요청.
- 종료: 유보. 재진입은 새 주장, URL, 관찰이 생길 때.

B. 창업자가 URL 을 주고 페이지가 캡처된다.
- 입력: A 의 기록과 URL 하나. 브라우저가 status, excerpt, collectedAt 을 남긴다.
- 기대: research_completed. GPT 독립 호출이 없으면 counter_review_completed 가 아니다. synthesis_pending 또는 judgment_deferred.
- 보존: 캡처 원문과 URL. A 의 유보 문장.
- 다음 행동: 그 캡처에 대한 반대 검토가 없으면 판단 제공이 아니다.
- 재진입: 캡처 해시가 새것이면 reentry_required.

C. Gemini 는 수요, GPT 는 판매자 소개.
- 입력: B 의 같은 excerpt.
- 기대: 두 독립 호출이 있을 때만 counter_review_completed. conflicts 에 두 해석. unresolved true. judgment_deferred. 고객 행동이 없으므로 judgment_provisional 로 확정하지 않는다.

- 다음 행동: 결제나 재구매 같은 관찰 하나. 같은 excerpt 를 다시 읽자고 하지 않는다.
- 현재 코드는 GPT 호출이 없으므로 이 시나리오의 counter_review_completed 는 미완성이다.

D. 새 근거 없이 같은 미확인을 다시 묻는다.
- 입력: A 또는 C 이후. 새 해시 없음.
- 기대: nextAction 거절. 상태는 judgment_deferred 유지.

- 다음 행동: withhold. 같은 문장을 다시 내지 않는다.

E. 새 페이지 기록이 기존 판단을 바꾼다.

F. 브라우저 실패 또는 모델 실패.

- 재진입: 귀속 accepted 또는 rejected 가 관찰로 들어올 때. 모델 동의만으로는 안 된다.

- 기대: loop_budget_held. 성공도 실패도 아니다.
- 보존: 네 바퀴의 원문과 마지막 판단.
- 다음 행동: 추가 모델 호출 없음. 남은 미확인을 보여 준다.
- 재진입: 한도가 승인으로 늘어나거나, 모델 없이 붙일 관찰이 생길 때. 횟수 자체는 재진입 이유가 아니다.

I. 두 모델이 동의하고 외부 근거가 없다.
- 입력: 같은 시장 크기 문장. 캡처 없음.
- 기대: research_not_run. counter_review_completed 가 되어도 근거 grade 는 model_inference. judgment_deferred. 동의는 확신도를 올리지 않는다.
- 보존: 두 원문. 없는 URL 은 출처가 아니다.
- 다음 행동: 그 문장을 뒷받침할 URL 또는 관찰 하나.
- 현재 코드의 점수 65 와 mock URL 은 이 시나리오의 외부 근거로 세지 않는다.

J. 새 근거가 판단을 바꾸지 않는다.
- 입력: 새 캡처가 직전 판단의 미확인을 닫지 않는다. 종합이 본문을 유지한다.
- 기대: changed false. changeCauseIds 는 비어도 된다. 본문이 같기 때문이다. reentry_required 는 새 해시 때문에 한 번 돌았고, 그 결과 본문이 같으면 다음 재진입은 없다.
- 보존: 새 캡처와 같은 판단 해시.
- 다음 행동: 여전히 열린 다른 미확인이 있으면 그것 하나. 같은 질문을 반복하지 않는다. 열린 것이 없으면 judgment_deferred 의 검증 계획을 유지한다.
- 종료: 고객 관찰이 없으면 판단 완료가 아니다.

5. 비용·보안 경계

키가 없는 이 셸.
- 연구 경로의 fetch 는 ensureConfigured 이전으로 가지 않도록 되어 있다. 호출 테스트는 하지 않았다.
- chatWithFallback 은 OPENAI_API_KEY 가 없으면 1차 오류를 다시 던진다. 이 환경에서는 폴백 fetch 도 없다.
- packages/agents 연구 어댑터는 키가 없으면 mock 을 반환한다. mock 은 네트워크가 아니지만 조사 완료도 아니다.

향후 승인용 분리. 지금 승인하지 않는다.
- Gemini: 바퀴당 1요청. model google/gemini-2.5-flash. endpoint OpenRouter. 가정 입력 8,000, 출력 2,000.
- GPT: 바퀴당 1요청. model gpt-4o-mini. endpoint api.openai.com. 같은 토큰 가정. 현재 연구 경로는 이 요청을 만들지 않는다.
- 종합: 바퀴당 1요청. 모델은 승인 때 정한다. 표결이 아니다.
- 재시도: ChatService 가 429 와 5xx 에서 최대 4시도. 실패 재시도는 성공 요청과 따로 센다.
- chatWithFallback 을 루프에 붙이면 5xx 이후 GPT 요청이 한 번 더 생길 수 있다. 루프 명세는 그 함수를 쓰지 않는다.
- 저장소 DEFAULT_PRICING 추정. 오늘 공급자 가격이 아니다. 입력 1M 당 0.15 USD, 출력 1M 당 0.6 USD 가 두 모델 표에 같다.
- 시도 1회의 추정은 0.0024 USD. 바퀴 3요청은 0.0072 USD. 4바퀴는 0.0288 USD. 매 요청이 4회까지 재시도되면 약 0.115 USD. 최대 지출 제안은 그 0.115 USD 를 넘기면 loop_budget_held 다. 승인 전에는 0 이다.

개인정보와 비밀.
- 현재 연구 프롬프트는 프로젝트 제목, 산업, 과제 이름을 모델에 넣도록 되어 있다. 페이지 HTML 은 넣지 않는다.
- 제안 루프가 대화와 발췌를 제3자 모델에 보내는 것은 아직 구현이 아니다. 보내기 전에 승인할 경계는 다음이다. 세션 쿠키, 인증 헤더, API 키, 비밀번호, 결제 원문의 불필요한 식별자, 전체 HTML 은 보내지 않는다. URL 과 짧은 발췌도 사업 정보가 제3자에게 간다.
- sessionStorage 의 대화는 그 브라우저 안에 있다. 그 사실만으로 조사 원본이 보존되지는 않는다.
- 소비자용 Gemini 또는 GPT 웹사이트를 브라우저로 조작하는 코드는 없다. 약관과 접근 방법을 확인하지 않았다. 그 자동화가 허용된다고 적지 않는다. API endpoint 가 코드에 있다는 것은 약관 검토가 끝났다는 뜻이 아니다.

6. 실행 보고서

코드 변경: 이 명세 파일과 루프 문서의 한 줄 연결뿐이다. 런타임 코드는 바꾸지 않았다.
테스트: 실행하지 않았다.
네트워크: 모델 호출 없음. 브라우저 호출 없음. 키 설정 없음.
정적 확인: 위 파일의 호출 순서와 이 셸의 키 unset.
미확인: Production 환경 변수, 키가 있을 때의 실제 응답 model, 화면 시나리오 A–J.

미해결과 승인.

GPT 독립 호출은 미완성이다. openai 라는 공급자 이름은 Gemini 경로다.
실패 시 mock 과 점수 대체가 조사 완료처럼 보일 수 있다. 루프 상태는 그 대체를 research_completed 로 받지 않는다.
브라우저 실패가 이전 캡처를 반환하지 않는 제품 crawl() 은 그대로다.
sessionStorage 는 조사 원본 저장소가 아니다.
구현 승인은 보류다. 필요한 승인은 GPT 를 다른 model id 와 endpoint 로 부르는 변경, 지출 한도, DB 또는 다른 지속 저장, 브라우저 자동화, 제3자 전송 범위다. 병합과 Production 배포는 그 전이 아니다.
