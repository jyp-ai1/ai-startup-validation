===== 3. 네 필드의 독립과 closeReview =====

hypothesis.outcome. evaluateHypothesis 만 쓴다. 값은 not_run, insufficient_record, passed, failed, conflict_unresolved. 가설 하나의 failed 는 그 가설의 판정이다. 전체 검토 완료가 아니다.
stageId 와 verdictId. evaluateStage 만 쓴다. outcome 을 읽는다. reviewCompletion 과 runStatus 를 쓰지 않는다.
runStatus. open, budget_held, provider_limited, provider_down. 운영 함수만 쓴다. 단계와 검토 완료를 바꾸지 않는다. 기본 경로에는 모델이 없으므로 budget_held 는 초안기가 승인되기 전에는 쓰이지 않는다.

필수 검토 집합. 고정 id 다. 입력 순서와 critical unknown 이 이 집합을 바꾸지 않는다.
h-customer. h-problem. h-payer. h-business-model. h-repeat.

closeReview 의 반환. reviewCompletion. blockingHypothesisIds. blockingConflictIds. 테스트는 세 값을 모두 관측한다.
closed_complete 의 조건은 셋이 동시에 참일 때만이다.
1. 일곱 항목이 현재 머리를 렌더한다.
2. 필수 검토 집합의 모든 outcome 이 passed 또는 failed 다.
3. 장부의 어떤 가설도 outcome 이 conflict_unresolved 가 아니다.
하나라도 거짓이면 reviewCompletion 은 closed_complete 가 아니고, 막힌 id 가 반환 배열에 있다. critical unknown 하나의 passed 나 failed 는 이 조건의 입력이 아니다. S3 이거나 S4 인 것도 조건이 아니다.

decision_ready. 일곱 항목이 렌더되고 다음 행동이 있으며, closeReview 의 완료 조건이 아직 거짓이다.
closed_incomplete. 창업자가 멈추거나 세션이 끊길 때 완료 조건이 거짓이다. 장부는 유지한다. 성공이 아니다.
S3 이고 h-business-model 만 passed 이고 h-repeat 가 not_run 이면 closeReview 는 closed_complete 가 아니다. blockingHypothesisIds 에 h-repeat 가 있다. reviewCompletion 은 decision_ready 다.
S4 이고 h-repeat 가 passed 여도 closeReview 를 호출하기 전에는 closed_complete 가 아니다. 호출 시 필수 집합의 나머지가 passed 또는 failed 이고 충돌이 없을 때만 closed_complete 다.
runStatus budget_held 는 reviewCompletion 을 closed_complete 로 만들지 않는다.
질문 수, 갭 CLOSED, 모델 호출 수는 네 필드 중 어느 것도 직접 쓰지 않는다.
