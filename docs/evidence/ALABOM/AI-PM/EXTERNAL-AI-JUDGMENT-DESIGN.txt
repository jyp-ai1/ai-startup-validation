4. 종합 판단 데이터 계약

구현 파일이 아니다. 외부 AI가 반환하는 JSON 의 계약이다. 모델 응답을 이 모양으로 파싱하지 못하면 판단은 바뀌지 않는다.

출처 등급.
- founder_claim: 창업자가 말한 문장.
- page_record: 저장된 URL 원문 발췌에 있는 문장. 페이지가 사실이라는 뜻은 아니다.
- model_inference: 역할 A, B, 종합 검토자의 추론.
- observed_outcome: 인터뷰, 파일럿, 결제, 재구매처럼 관찰된 결과. 이 단계의 모델이 만들지 못한다.

VALIDATED 는 이 계약의 등급이 아니다. 모델이 그 단어를 써도 저장 전에 거절하고 model_inference 로 바꾸지 않는다. 그 항목은 누락으로 남긴다.

타입 스케치.

JudgmentSourceRef
- id: string
- grade: founder_claim | page_record | model_inference | observed_outcome
- text: string
- sourceUrl: string | null
- collectedAt: string | null
- excerpt: string | null

OpposedSource
- sourceId: string
- text: string

SynthesisSection
- text: string
- sourceIds: string[]
- opposedSourceIds: string[]
- uncertainty: string
- missingCheck: string

ExternalSynthesisJudgment
- executiveJudgment: SynthesisSection
- whyCanWin: SynthesisSection
- whyFail: SynthesisSection
- evidenceMap: JudgmentSourceRef[]
- criticalUnknown: SynthesisSection
- decisionChangingEvidence: SynthesisSection
- validationPlan: SynthesisSection
- agreementWithoutSource: boolean
- roleDisagreement: string

각 섹션의 sourceIds 가 비어 있으면 그 섹션은 근거 없는 추론이다. agreementWithoutSource 가 true 이면 확신도를 올리지 않는다. 숫자 확신도는 필수 필드가 아니다. 기존 연구 경로의 65 점 대체를 가져오지 않는다.

역할 A는 시장, 고객, 경쟁, 가격의 근거와 반대 근거를 찾는다.
역할 B는 사업 모델의 약점, 반례, 실패 조건, 빠뜨린 가정을 찾는다.
종합 검토자는 둘의 일치와 충돌을 적고, sourceIds 가 page_record 또는 founder_claim 또는 observed_outcome 을 가리키는지 본다. 모델끼리의 같은 문장은 새 출처가 아니다.

- disagreements: { topic: string, leftRole: string, rightRole: string, assumption: string, resolution: string | null }[]
- finalJudgment: ExternalSynthesisJudgment | null
- judgmentHistory: { at: string, reason: string, previousHash: string, nextHash: string }[]
- observations: { observationId: string, kind: 'interview' | 'pilot' | 'payment' | 'repurchase' | 'other', text: string, observedAt: string | null, sourceUrl: string | null }[]
- evaluation: { rubricId: string, scores: Record<string, string>, evaluatorNote: string | null, observedFactIds: string[] } | null

observations 가 비어 있으면 accuracyStatus 는 unverified 다. 평가자의 evaluatorNote 는 observed fact 가 아니다. evaluation.observedFactIds 만 관찰 기록을 가리킨다.
사업 결과가 없으면 정확도가 검증된 세션으로 세지 않는다.
최종 판단이 바뀌면 judgmentHistory 에 이유와 해시를 남긴다. 이전 판단을 덮어 지우지 않는다.

저장 위치는 이 문서가 정하지 않는다. 기존 Evidence 테이블은 sourceUrl 과 summary 는 있으나 등급, 원문 발췌, 역할, 충돌, 관찰 결과를 나누지 못한다. 그 테이블에 모델 요약을 넣는 현재 persistResearchEvidence 를 이 계약의 저장으로 쓰지 않는다. DB 마이그레이션은 별도 승인이다.

6. 판단 품질 평가 계획

비교 대상은 두 개다.
기존 방식: analyze-strategic-intelligence.ts 에 창업자 문서만 넣는다. 외부 페이지를 넣지 못한다.
제안 방식: 같은 창업자 문서와, 그 문서에 적힌 URL만 회수한 pageCaptures 를 넣는다. 역할 A, B, 종합 검토자를 거친다.
규칙 엔진의 출력을 정답으로 두지 않는다. 외부 AI의 출력을 정답으로 두지 않는다.

사례를 만들 때 입력과 결과를 분리한다.
입력 봉지에는 창업자 주장과 허용 URL만 있다.
결과 봉지는 인터뷰, 결제, 재구매다. 두 방식이 판단을 낸 뒤에 연다. 결과가 없는 사례는 정확도 칸을 unverified 로 둔다.
입력 봉지에 결과 문장이 들어 있으면 그 사례는 무효다.

평가 항목. 점수는 숫자가 아니라 기록이다.

- 근거 추적: 각 결론 문장이 sourceId 를 가지고, 그 id의 excerpt 안에 기대는 문장이 있는가.
- 사실과 추론: page_record 와 model_inference 와 founder_claim 이 한 문장 안에서 섞여 한 등급처럼 보이지 않는가.
- 누락: 입력 봉지의 반대 문장이나 실패 조건이 whyFail 또는 disagreement 에 있는가. 없으면 누락이다.
- 수정: 결과 봉지를 열기 전에, 새 page_record 하나를 추가했을 때 judgmentHistory 가 생기는가. 같은 문장을 유지하면 유지 이유가 있는가.
- 불확실성: criticalUnknown 과 missingCheck 가 비어 있지 않은가. 근거가 없는데 단정 문장만 있는가.
- 관찰 일치: 결과 봉지가 있을 때만. 판단이 그 관찰과 같은가, 반대인가, 판단이 그 관찰을 말하지 않았는가. 성공 사례 수로 모델 정확도를 결론내지 않는다.
- 비용과 시간: 모델 호출 수, 저장소 가격표로 계산한 추정 비용, 크롤 시간과 모델 시간. 실패한 호출도 포함한다.

같은 모델의 A와 B가 같은 문장이어도, page_record 가 없으면 추적 항목은 실패다.

7. 실제 사업 통합 검증 시나리오

사례 이름은 배송 소상공인 입력이다. 미병합 시드 문장을 입력으로만 쓴다. 이 시나리오는 그 사업의 성패를 알고 있다고 말하지 않는다.

입력 봉지.
- 고객 주장: 반찬가게·꽃집 등 직접 배송 소상공인.
- 문제 주장: 주문과 배송을 따로 관리해야 함.
- 수익 주장: 월 구독.
- 창업자가 URL을 주기 전에는 pageCaptures 가 비어 있다. 빈 상태를 성공으로 채우지 않는다.
- 창업자가 URL을 주면 그 URL만 연다.

사용자에게 보이는 것.
- 사업 판단 한 문장. executiveJudgment.text.
- 될 수 있는 이유와 실패 위험.
- 근거 목록. 각 항목에 등급과 URL 또는 창업자 주장임이 보인다.
- 아직 모르는 것. criticalUnknown.
- 판단을 바꿀 증거. decisionChangingEvidence.
- 다음 검증 행동. validationPlan. 실행 완료로 표시하지 않는다.

사용자에게 보이지 않는 것.
- 브라우저가 연 과정, 스크린샷 도구 로그, 역할 프롬프트, 재시도 횟수.
- 규칙 엔진의 단계 이름 S0–S4 를 사업 성패로 번역한 문장.
- 모델이 합의했다는 문장만으로 된 확신.

내부 순서.
1. 창업자 주장을 founder_claim 으로 저장한다.
2. URL이 있으면 브라우저가 연다. 실패하면 error 를 남기고 판단을 만들지 않거나, 문서만으로 만든 판단임을 표시한다.
3. 역할 A와 B가 같은 패킷을 읽는다.
4. 종합 검토자가 충돌을 적는다.
5. 화면은 7개 필드만 그린다.
6. 이후 결제나 재구매가 관찰되면 observations 에 넣고, 그 전 판단과 비교한다. 관찰 전에는 unverified 다.

이 시나리오를 이번 검토에서 화면으로 실행하지 않았다.

8. 최소 구현 범위, 비용, 위험

승인 뒤에 처음 만들 범위. 이번 커밋에는 없다.

- 위 두 계약의 타입과, VALIDATED 와 빈 출처와 대체 점수를 거절하는 순수 함수.
- 로컬 HTML 픽스처로 그 함수를 검사. 네트워크와 모델은 이 검사에 없다.
- crawlPages 결과에 collectedAt, HTTP 상태, error 를 남기는 변경. 검색 기능은 없다.
- 화면은 기존 판단 한 칸, 다음 행동 한 칸을 7개 필드로 바꾼다. 브라우저 조작은 숨긴다.
- 모델 호출은 키와 지출 한도가 승인된 뒤에만 연결한다. 승인 전에는 픽스처 JSON 으로 화면 경로를 검사한다.
- DB 마이그레이션은 첫 범위에서 뺀다. 세션 저장이 필요하면 승인된 저장소에 둔다.

비용.
- 지금: 모델 0 USD. Chromium 로컬 설치는 API 과금이 아니다.
- 승인 후 같은 모델 3회, 위 가정: 약 0.007 USD 한 건. 긴 페이지와 재시도는 별도다.
- 다른 유료 모델, 검색 API, 호스팅된 브라우저 풀은 이 최소 범위 밖이다.

위험.
- 모델이 URL과 숫자를 만들어도 현재 연구 경로가 받을 수 있다. 최소 범위는 저장된 pageCaptures 에 없는 sourceId 를 거절해야 한다.
- 같은 모델의 두 역할은 같은 오류를 공유한다. 독립 검증으로 보고하지 않는다.
- 페이지에 문장이 있어도 그 페이지가 사실인 것은 아니다. page_record 와 observed_outcome 을 나눈다.
- 사이트 이용 조건과 로그인 페이지는 확인하지 않았다. 최소 범위는 창업자가 준 공개 URL만 연다.
- 규칙 엔진을 지우면 등급 가드와 충돌 보존까지 사라질 수 있다. 중단 제안은 삭제 승인과 분리한다.
- 테스트 통과를 정확도로 읽는 위험이 남아 있다. 평가 계획의 accuracy 는 관찰 봉지가 있을 때만 적는다.
- PR #197 의 모름 반복과 결제 주체 오분류는 그대로다. 이 설계가 그 결함을 고치지 않는다.

CPO 판단이 필요한 것.

최소 구현 범위를 승인할 것인지. 모델 키와 지출 한도를 언제 열 것인지. 규칙 엔진 중단 제안을 삭제 없이 유지할 것인지. DB를 열지 않고 세션을 어디에 둘 것인지.
