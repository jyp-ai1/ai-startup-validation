S3. 질문 선택 — 판단을 바꿀 가능성이 가장 큰 미확인을 고르는가

S4. 답변의 영향 평가 — 어떤 판단·근거가 바뀌었는지 추적하는가
부분 구현. TraceBusinessChoiceImpact, judgment traces 존재. 질문 선택 SoT에 연결되지 않음. 「영향이 없으면 왜 추가 질문이 필요한가」를 창업자에게 설명하는 분기는 공백.

S6. 단계 판정 — 주장을 검증된 사실로 승격하지 않는가
부분 위반. MCQ specific hint는 ASSUMPTION. on-slot VALID는 FACT/CLOSED. 로그인 UI S4 T2 고객 선택, T3 문제 선택(질문과 안 맞는 보기 클릭 가능) 후 즉시 CLOSED.

객관식 원칙 A. AI 이해를 먼저 보여주고 확인받는가
부분 구현.

실제질문: 이 서비스를 가장 필요로 하는 사람은 누구인가요?
보기: 맞벌이 부모 / 아이 간식을 매주…대상 / 기타 / 아직 모르겠음
선택: 맞벌이 부모 (또는 아이|부모 매칭)
반영: customerPersona CLOSED. 선택=사실 승격.
판단: 고객 차원 채움. 사업성 재계산 증거 없음.
다음: problemJtbd. 고객을 「아이」로 골랐어도 다음은 같은 문제 질문이다 (시퀀스 고정).

T3
질문갭: problemJtbd
실제질문: 고객이 지금 가장 불편해하는 점은 무엇인가요?
보기: 장을 볼 시간이 없고 과자 고르기가 피곤하다 / 장… / 아이 간식을…대상 / 기타 / 아직 모르겠음
선택: 하니스가 /아이|부모/ 에 매칭되면 문제 질문이 아닌 보기를 누를 수 있음. 그래도 problemJtbd CLOSED.
이해: 문제 슬롯에 고객 문구가 들어가도 갭은 닫힌다.
다음: payer (T7: customer+problem CLOSED → next=payer). T7는 여기서 의도대로 동작.

T4
질문갭: payer
실제질문: 도입을 결정하는 사람은 누구인가요?
선택: 부모 계열 보기
반영: payer CLOSED
다음: alternativesCompetitors. S1-S6와 동일. 「실제 지불 의사 vs 기존 대안 vs 확보 가능성」 중 최대 위험을 고른 결과가 아님. Stage B 첫 칸.

T5-T6
질문갭: alternativesCompetitors 반복
질문: 「비슷한 역할을 이미 하고 있는 서비스가 있나요?」 또는 문서 에코 confirm
입력: first-specific 또는 confirm-yes 후 submit-failed
종료: 같은 표면이 반복. 8턴 미도달. 검증 행동으로 전환 없음.

같은 문서의 Track B 엔진 어댑터 (참고, UI 아님)
시퀀스: customerPersona → problemJtbd → solution → customerPersona 회귀 → payer ×4
이해: 고객이 T1에서 CLOSED 되지 않으면 FIX-10이 solution으로 가고, 이후 고객을 다시 묻는다.
판단: payer unknown 반복은 T7 유지 + unknown이 payer를 닫지 못함. 반복 원인이 「판단 무변화」로 기록되지 않고 anti-repeat 리프레임만 돈다.
품질: NEEDS FIX. 8턴 ≠ 성공.

===== 5. 반복 질문과 갭 회귀의 근본 원인 =====

원인 1. 질문 SoT가 판단이 아니라 갭 completeness 순서다.
같은 갭이 OPEN이면 다시 그 갭을 고른다. 답이 판단을 바꿨는지 보지 않는다.

원인 2. 순서 계약이 두 개다.
Stage A: customer → payer → problem.
FIX-10: customer → problem → solution.
T7: customer+problem CLOSED → payer.
고객이 안 닫히면 FIX-10이 solution으로 가고 고객이 나중에 회귀한다 (Track B S1/S3/S4). 고객이 닫히면 T7이 payer를 붙잡는다 (로그인 UI). 둘 다 「열린 칸」 논리다.

원인 3. anti-repeat는 원인을 식별하지 않고 문구를 바꾼다.
「조금 더 구체적으로 알려 주세요」는 같은 갭의 재질문이다. 판단 무변화·unknown·PARTIAL의 구분이 선택 엔진을 바꾸지 않는다.

원인 4. MCQ specific 이 갭을 닫아버린다.
문서 조각 클릭 = CLOSED. 잘못된 슬롯 보기도 닫을 수 있다. 닫힌 갭은 잠시 사라지고, 다른 순서 규칙이 다음 칸을 당긴다. 나중에 이해가 흔들리면 회귀한다.

원인 5. unknown + T7 은 payer 루프를 만든다.
unknown은 올바르게 payer를 닫지 않는다. T7은 payer를 다시 고른다. Track B S1 T5-T8.

원인 6. Stage B 진입이 항상 alternatives부터다.
답 내용과 무관. 로그인 UI가 여기서 문서 confirm 루프에 걸린다. 반복의 UI 표면.

이것이 anti-repeat 한 함수의 버그가 아닌 이유: 새 답이 이해·판단을 얼마나 바꿨는지 묻는 SoT가 없다.

===== 6. 최소 아키텍처 개선안 및 회귀 위험 =====

제안만. 이 문서로 구현하지 않는다. CPO 검토 전 리팩터링 없음.

방향 A — 유지할 바닥
T6 buyer≠payer 차단 유지.
T7 customer+problem CLOSED 이고 payer OPEN 이면 payer를 건너뛰지 않음 유지.
Stage A 네 갭을 「비어 있으면 안 되는 바닥」으로 유지하되, 질문 순서 SoT로는 쓰지 않는 방안을 CPO가 결정.
5263e83e 문구를 엔진에 맞추지 않음.
AC16/AC5 기대값 미하향.

방향 B — 한 턴의 올바른 중심 (구현 전 설계만)
1. 문서+답변으로 CurrentUnderstanding (종합 문장) 을 만든다.
2. CurrentViabilityJudgment (근거 / 실패 위험 / 핵심 불확실성) 을 갱신한다. SI와 AI PM 경계를 명시.
3. 다음 행위 = 그 판단을 가장 흔들 미확인. 질문 또는 검증 행동.
4. 객관식 = 그 미확인에 대한 AI의 잠정 이해를 보여주고, 창업자가 정확/수정/틀림/유보를 고른다.
5. 선택 결과는 판단 입력이다. specific 클릭만으로 VALIDATED/CLOSED 하지 않는다.
6. 영향이 0이면 같은 칸을 리프레임하지 말고, 왜 더 묻는지 또는 검증 행동으로 넘길지 기록한다.

회귀 위험
판단 우선으로 순서를 바꾸면 T7 재검증이 필요하다. payer를 「영향이 작다」고 건너뛰면 CPO VERIFIED가 깨진다.
specific을 CLOSED에서 내리면 Track B 8턴·기존 갭 테스트가 대량 실패한다. 실패를 숨기면 안 된다.
MCQ 보기 품질을 시나리오 휴리스틱으로 더 맞추면 테스트에 제품이 맞춰진다. 금지.
SI를 매 턴 호출하면 비용·지연·모의 데이터 위험이 있다. 연결 설계와 별개로 런타임 LLM 승격은 CPO 게이트.

Q2. 객관식 specific 선택이 갭을 CLOSED/FACT로 승격해도 되는가. 전략 문장은 안 된다고 한다.
Q3. AI 이해 확인의 기본 UX를 4분 객관식(정확/수정/틀림/유보)으로 바꿀 것인가. 현재는 이진 확인 + 갭 MCQ.
Q4. 대화 루프가 매 턴 SI 사업성 판단을 호출해야 하는가, 아니면 AI PM 내부 CeoJudgmentState를 사업성 SoT로 키울 것인가.
Q5. 질문보다 검증 행동이 맞을 때, 워크스페이스가 질문을 멈추고 실행 카드로 가도 되는가.
Q6. FIX-10 customer→problem→solution 과 Stage A customer→payer→problem 중 무엇을 제약으로 남길 것인가. 둘을 동시에 SoT로 두면 회귀가 재발한다.

===== 핵심 진단 (증거) =====

이미 입력된 사업 정보를 다음 질문 선택에 충분히 활용하는가
아니오. 문서는 보기와 요약을 채운다. 다음 갭은 열린 Required 순서다.

답변이 들어오면 사업성 판단이 실제로 갱신되는가
부분. CeoJudgmentState와 living summary는 다시 그려진다. 앱 내부 SI는 원라이너 문구만 덮을 수 있고, @repo/agents 및 SI 판단은 다음 갭 SoT가 아니다.

다음 질문은 열린 갭 때문인가, 판단 영향 때문인가
열린 갭 때문이다. pickNextRequiredGap, Stage B judgmentFirst, T7/FIX-10.

같은 질문을 반복할 때 원인을 식별하는가
아니오. anti-repeat는 리프레임한다.

새 답이 판단에 영향을 못 줬다면 이유를 추적할 수 있는가
테스트 헬퍼는 있다. 런타임 선택 입력은 아니다. 로그인 UI T5-T6은 영향 없이 같은 표면이다.

질문보다 고객 검증이 맞을 때 검증 행동을 고를 수 있는가
공백. nextValidationAction은 다음 질문 whyNow의 별칭이다.

FACT / CLAIM / INFERENCE / ASSUMPTION / VALIDATED 가 구분되는가
이름은 흩어져 있다. CLAIM 타입은 없다. 객관식 확정이 FACT/CLOSED로 이어질 수 있어 단계 판정 원칙과 충돌한다.

객관식이 AI 이해를 보여 주고 검증하는가
화면 부품은 있다. 기본 경험은 아직 「다음 빈칸을 고르는 객관식」이다. 선택 결과가 다음 판단을 갈라지 않는다는 증거가 로그인 UI S1-S6 동일 시퀀스다.
